# 第七课执行控制实施计划

**目标：** 完成已发布的[第七课六项任务](../../learning/07-deadlines-cancellation-and-capacity.md)，提供共享截止时间、单进程取消、有界容量与如实的清理状态；发布第八课。

**授权：** 用户要求完成第七课，包含任务六的集中验收、少量真实模型调用及页面验收；沿用每项细分提交并 push 的授权。现有任务包已明确设计，本次直接落地；保留所有无关工作区改动。

**结构：** `runtime` 包持有控制对象和租约，Task / Prompt 不携带控制数据。运行协调线程、阻塞模型线程分开限额。总截止时间从提交时开始，以 nanoTime 计算；单阶段等待只能缩短。RunRegistry 保留终态但不丢失未清理占用。取消决定业务终态，实际 Future 结束才释放 Agent 与调用许可。

- [ ] 1. `ExecutionControl` / `RuntimeSettings`：可控时钟、预算校验、协作停止与一次释放租约；先增加专项断言。
- [ ] 2. `RunRegistry` / `ExecutionRuntime`：有界运行队列、有限工作线程、模型许可、角色租约、保留期限和登记容量；排队取消移除、超时不出队。
- [ ] 3. Orchestrator / BaseAgent：共享阶段时间、取消后不调度、保留迟到清理、有限客户端超时；复用第六课原子终态。
- [ ] 4. Controller：提交即返回 executionId（流式首个 report）、GET 查询与 POST 取消；同步入口兼容。关闭连接不取消。
- [ ] 5. Vue：预算输入、取消按钮、排队和清理状态、断连后的当前运行查询；中英文。

## 设计决策

- 采用本地登记表 + 有界协调线程池；保留现有 Java / Spring Boot 结构。持久化和多实例协调留第九课。
- 运行队列 FIFO；角色等待采用 FIFO 领取列表；实例一份租约（capability.maxConcurrency 为该实例上限，当前实现固定单任务），通过注册多个实例扩容。模型调用另有限额。
- 默认总预算 90 秒，最大 180 秒；规划/任务/汇总上限分别 60/120/60 秒，但都受总预算限制。默认同时协调 2 项运行、排队 8 项、模型调用 3 项。
- 不调用 Future.cancel 冒充已停止 HTTP；同步 ChatClient 路径配置底层超时，真实返回前如实保留占用。新增模型/工具动作必须通过运行控制检查入口。
- 运行取消和截止时间会结束所有未终结 Task；正常失败仍沿用第六课失败因果。终态记录可查、清理状态独立更新。

## 验收范围

使用 latch、可控 Future 和注入时钟验证：排队耗尽预算、规划取消、并行取消、迟到完成、重复取消、跨运行隔离、容量拒绝、排队移除、模型限额、观察异常、保留与清理。禁止随机 sleep 作为正确性依据。通过本课专项 Maven 选择器运行；前端正常构建。真实模型只验证当前供应商路径，不能据此证明所有客户端可中断。
