# 第十三课：检索、混合召回与重排

状态：**完整学习任务包，尚未实现、尚未验收**。编写日期：2026-10-24。正式存储主线为 PostgreSQL + pgvector，SimpleVectorStore 仅作原理对照和离线单元测试。

适合已经能编写 Spring Boot 接口的学习者。本课沿用“企业知识库与工单助手”，把第十二课维护的有效文档变成**可解释、可测量的候选证据**。每次完成一个单元；六个单元组成同一个功能闭环，不要求一天全部读完。

## 1. 先理解：有向量，不等于找对资料

用户问“VPN 报 809 怎么办”。语义检索可能找到“VPN 连接失败”的通用手册，关键词检索可能更擅长命中错误码 809。两路召回合并后，再判断哪段最能回答当前问题，才适合交给模型。

```text
原问题 + 服务端可信的访问范围
    ↓ 可选查询改写（保留原问题）
精确向量召回 ─┐
关键词召回 ───┴→ 按稳定 chunk 身份去重 → RRF 融合
    → 可选重排 → 最终有效性检查 → TopK 候选证据
    → 第十一课上下文预算 → 第十四课引用与无依据回答策略
```

| 概念 | 含义 | 熟悉的后端类比 |
| --- | --- | --- |
| 召回 retrieval | 从当前允许使用的资料中取候选 | 带条件的数据库查询 |
| 精确向量检索 | 在过滤后的向量上计算距离、排序 | 全量候选的确定性排序基线 |
| 近似检索 ANN | 用索引减少搜索成本，可能漏掉候选 | 以部分召回损失换取性能 |
| 关键词检索 | 用词项、错误码或产品名寻找匹配 | 可解释的文本查询 |
| 混合召回 | 合并不同检索路径的结果 | 多个数据源的结果归并 |
| RRF | 按每一路的排名贡献融合分数 | 不直接相加不同量纲的分数 |
| 重排 rerank | 对少量候选重新判断与问题的相关性 | 召回后的第二阶段排序 |
| relevance label | 人工标注的相关程度 | 回归测试的期望结果 |

**本课验收检索链路，不把“模型回答流畅”当作检索有效的证明。** 文档发布和删除仍由第十二课负责，答案逐项引用由第十四课负责。权限过滤需要贯彻本课查询，但完整身份认证与权限管理仍在后续课程深化。

## 3. 本课功能目标与预算契约

同一检索请求应包含原问题、可信的租户/可读范围、索引 generation、每路候选上限、最终 TopK 和统一截止时间。客户端可以提交问题与经过限制的检索选项，**不能自行声明自己属于别的租户或具有管理员权限**。尚无完整登录的实验环境必须明确标注为服务端固定演示身份。

每条返回候选至少包含：

- `documentId`、`revisionId`、稳定 `chunkId`、generation、来源位置和文本。
- 命中的通道、各通道原始 rank/score、融合分数、可选重排分数。
- 当前访问范围与有效版本检查结果；对外不暴露无权资料的标题、文本或调试分数。
- traceId、实际使用的改写、降级原因、阶段耗时、请求预算与实际候选数。

建议先固定：每路最多 20 条、最终最多 5 条、重排最多 20 条、改写最多 1 次。数值是本课实验起点，需按真实实测调整，不能称为生产最佳值。统一 deadline 包含改写、查询、融合和重排；SQL/HTTP 超时要从剩余预算计算，剩余不足时停止后续可选阶段。

## 4. 单元一：先建立问题与期望证据集

### 概念

没有固定问题集，今天换模型、明天改切块，很容易凭几个顺眼的回答判断“提升了”。先固定资料、问题和人工判定，再比较方案。

### 实践任务

1. 建立合成资料集：VPN 809、VPN 691、账号锁定、密码重置、打印机工单；加入相似但不相关段落、旧版手册和另一个演示租户的同名资料。
2. 建立至少 20 条问题，覆盖中文口语、英文错误码、缩写、同义表达、多意图、无答案和权限排除。每条具有稳定 `queryId`。
3. 为问题标注期望的 `documentId + revisionId + chunkId`，相关程度用 0/1/2，注明人工判定理由。把“禁止出现”的旧版本/其他租户片段单独列出。
4. 固定切块与资料快照；若重新切块造成 chunkId 改变，显式更新评测集版本与映射，不把旧标签静默套到新索引。
5. 将小样本分为调参集与留出集；先确定验收门槛再看留出结果。20 条仅为教学起点，不能外推企业真实问题分布。

示例标签（字段是建议格式）：

```json
{
  "queryId": "vpn-809-zh-01",
  "question": "VPN 提示 809，先排查哪里？",
  "scope": "tenant-a-helpdesk",
  "relevant": [
    {"documentId": "vpn-guide", "revisionId": "r2", "chunkId": "vpn-r2-809", "grade": 2}
  ],
  "forbidden": ["tenant-b-vpn-809", "vpn-r1-809"],
  "reason": "命中当前版本的 809 排查步骤"
}
```

**交付与验收：** 资料快照、问题集、标签校验器和人工标注说明。测试发现重复 queryId、不存在的目标块、标签版本不匹配时明确失败。

## 5. 单元二：建立真实 PG 精确向量检索基线

### 概念

先证明同一向量空间内的精确距离排序正确，再评估近似索引。查询与文档必须使用相同模型身份、维度、预处理和距离度量，不能仅因长度相同就认定两个模型的向量可比较。

### 实践任务

1. 复用第十二课记录的 embedding/generation 契约；模型身份或维度不匹配时拒绝查询。校验空向量、零向量的度量适用性、NaN、Infinity 和 TopK 范围。
2. 在真实 PG 查询中先约束租户、可读范围、未删除文档、active revision、generation，再按距离排序并加稳定 ID 次排序。SQL 必须参数化，不能拼接客户端过滤表达式。
3. 用可控向量在真实 PG 中验证距离排序与过滤。此项证明数据库行为，**不证明真实 Embedding 的中文语义能力**。
4. 使用固定模型的真实向量运行同一问题集，另记模型身份、文档/查询输入规则、维度、时间与费用。不可用时报告真实语义评测未执行。
5. 如果第十二课已建 HNSW/IVFFlat，保留明确的精确基线实验路径。使用实际查询计划确认基线路径，没有执行近似扫描；不要只把同一个近似查询改名为 exact。
6. 对照 ANN 与精确基线的结果、耗时和过滤后返回数量。记录索引和会话参数；小资料集不宣称性能提升。

pgvector 官方说明区分精确与近似检索，近似查询的过滤可能影响最终返回数量；实验按第十二课固定的扩展版本核对可用行为，不能假定新版本的迭代扫描功能已存在。[pgvector 官方项目](https://github.com/pgvector/pgvector)

**交付与验收：** PG 集成测试、精确基线结果、模型空间不匹配测试、EXPLAIN 记录。数据库不可用时本单元阻塞，不能切内存继续声称 PG 已通过。

## 6. 单元三：补上中文关键词召回

### 概念

“809”“MFA”“VPN”是有价值的词项。中文自然语言没有天然空格，PostgreSQL 默认英文全文配置不能直接当作已经解决中文分词。

### 实践任务

1. 固定并记录中文处理方案：例如应用侧采用一个明确版本的分词器，保留错误码、英文缩写、产品名，生成确定的 token 序列。
2. 用真实输入输出检查 token：`VPN报错809`、`多因素认证失败`、`账户锁定`、混合标点和大小写。索引侧与查询侧使用同一规则。
3. 若采用 PG 全文索引，将应用生成的词项按已确认的配置写入并测试；`simple` 字典不等于中文分词器。处理用户特殊符号时使用参数化查询和明确的词项组合策略。
4. 初始方案也可用参数化子串匹配作为可解释基线，但必须标注为子串召回，记录扫描成本，不称其为 BM25 或完善中文全文搜索。
5. 两条通道都执行同一有效性与访问过滤。用错误码精确问题、同义表达问题比较关键词与向量的长处及漏召回。

PostgreSQL 的 parser 与 dictionary 分工需要分别理解，配置语言词典不能自动补足任意中文切词需求。[PostgreSQL 17 文本搜索词典](https://www.postgresql.org/docs/17/textsearch-dictionaries.html)

**交付与验收：** 可复现的分词示例、固定依赖、真实 PG 查询测试和关键词命中解释；未做中文分词或语义实测的部分明确标注。

## 7. 单元四：实现 RRF 与可替换重排

### 概念

向量距离越小越好，关键词分数通常越大越好，两者范围不同。RRF 根据名次融合，先不用直接相加原始分数。融合后，重排器再同时看问题与候选文本；重排无法找回召回阶段已经漏掉的资料。

本课使用以下明确约定作为自己的实现契约：

```text
RRF(chunk) = Σ channelWeight / (rankConstant + oneBasedRank)
```

每路先按稳定 chunk 身份去重，未出现的通道贡献 0；rank 从 1 开始。初始 `rankConstant=60`、两路权重均为 1，只作为待评测配置。融合分数相同再按稳定 chunkId 排序，保证结果可复现。

### 实践任务

1. 用手算示例写融合单元测试：同块双路命中、单路命中、重复块、空通道、同分、非法权重与 candidate 上限。
2. 去重键包含访问范围内的稳定 chunk 身份与版本；不把不同租户同名文件误合并。同一文档多个相邻块可在融合后按明确规则限制占比，保留来源解释。
3. 定义重排接口，输入原问题和最多 N 条已授权候选，输出候选 ID 与有限数值分数。校验未知 ID、重复 ID、漏项与 NaN，拒绝由重排器注入新的片段。
4. 提供确定性替身测试管线；若使用关键词规则作为本地重排，明确称为规则重排。另选定真实 reranker 及版本、截断策略、输入限制、超时和费用，独立运行真实质量评测。
5. 重排异常或预算不足时，返回已通过验证的 RRF 顺序并标记降级。不能返回空列表后假装“知识库没有答案”，也不能隐藏真实服务失败。

**交付与验收：** RRF 手算/单测、重排适配契约、真实重排报告或明确未执行状态。真实模型不可用不阻塞纯算法验证，但不能宣称重排提升已验证。

## 8. 单元五：查询改写、权限与失败边界

### 概念

改写可以补全口语表达，也可能把“没有锁定”改成“已锁定”。原问题是业务语义的依据，改写只能产生补充候选查询，不能修改用户意图或访问权限。

### 实践任务

1. 为现有 `QueryRewriter` 增加本课服务包装，保存 originalQuery 与 rewrittenQuery；限定输入长度、最多一次改写和总截止时间。
2. 同一预算内保留原问题召回路径；改写为空、超长、异常或超时，回到原问题并记录原因。不要通过不断重试耗尽整条链路。
3. 若合并原问题与改写问题的两份结果，先在通道内去重/归并，再按确定的通道权重融合，避免仅因为改写多一次就让向量通道获得双倍隐式权重。
4. 所有通道从服务端读取访问范围，查询前过滤，并在送往重排/模型前重新校验当前有效版本与权限。外部重排服务属于资料发送边界，未经授权的文本不能先发出去再过滤。
5. 检索过程中若文档切换版本或删除，最终检查剔除失效块；有上限地补取，不无限补齐。有效候选不足 TopK 时，返回实际数量与 shortageReason，不从旧版本或别的租户凑数。
6. 向量通道失败、关键词通道失败、全部通道失败分别制定策略。允许单路降级时明确标识；全部失败返回可识别的检索失败，区别于成功查询后的零命中。取消与 deadline 传播到外部调用，避免遗留任务占用资源。

**交付与验收：** 原问题保留、权限不被改写污染、版本切换/删除竞态、短缺与失败状态、预算和取消测试。展示日志只保留必要脱敏字段，不输出凭据或未授权文本。

## 9. 单元六：比较效果、延迟并截图验收

### 概念与指标

检索指标衡量“证据找得怎样”；端到端回答指标衡量“模型用了证据后答得怎样”。两类结果分别报告。

| 指标 | 本课计算约定 | 观察什么 |
| --- | --- | --- |
| Recall@K | TopK 中相关且去重的标签块数 / 全部相关标签块数 | 相关资料有没有被找回 |
| MRR@K | 第一条相关结果名次的倒数；K 内没有则为 0，再按问题平均 | 最先找到相关资料的位置 |
| nDCG@K | gain=`2^grade-1`，按 `log2(rank+1)` 折扣，再除理想 DCG | 多级相关性与顺序 |
| 权限/版本违规数 | 返回的禁止块数 | 作为必须为 0 的安全正确性门槛 |
| 延迟与预算 | 总耗时与各阶段 p50/p95、调用数、候选数、实际用量 | 改善是否值得付出成本 |

无相关标签的问题单列为 no-answer 组，不放入 Recall 的零分母。nDCG 的 IDCG=0 时单独报告未定义组；不要任意填 1 提高平均分。固定 K、并列排序、相关阈值与评测集版本。

### 实践任务

1. 在相同资料快照、访问范围、问题集和模型空间下比较：关键词、精确向量、RRF、RRF+真实重排。分别列调参集与留出集结果，不能只展示最好的一题。
2. 做消融：关闭改写、关闭重排、减少候选、启用 ANN；检查 Recall、排名、延迟和费用如何变化。保留所有配置与失败样本，不预设混合召回一定提升。
3. 延迟测试区分冷/热缓存、并发度、样本量、超时与错误，使用实际测量；合成小资料集和替身耗时不能代表真实模型生产性能。
4. 可补充真实模型端到端实验，独立评估答案正确性、证据覆盖和无依据断言。记录模型、提示词、资料版本与人工判断；第十四课再完善引用与拒答机制。
5. 前端复用统一业务/学习入口，显示原问题、实际存储 PG、通道、融合/重排次序、耗时和明确降级；不要展示模型私有思考链，把真实检索事件作为解释。
6. 按下表逐项点击后截图，记录操作、预期、实际、截图和控制台错误。按钮点击一次成功只是起点，反复切换和恢复也要覆盖。

## 10. 自动测试矩阵与交付边界

新增逻辑先写可复现的失败用例，再实现并回归。真实 PG 集成测试必须有独立命令与报告；缺少数据库配置时明确失败/阻塞，不使用静默 fallback，也不以 skipped 计为主线通过。

| 层级 | 必测场景 | 能证明的范围 |
| --- | --- | --- |
| 纯单元 | RRF 手算、rank 从 1 开始、去重、并列、指标手算、非法参数 | 排序与评测算法正确性 |
| 故障替身 | 改写空值/超时、重排异常/未知 ID、单路失败、取消、统一预算 | 服务编排和降级控制 |
| 真实 PG | 距离排序、过滤、active 版本、删除、并发版本切换、稳定分页/补取界限 | 实际 SQL、事务可见性与查询契约 |
| 真实模型 | 同空间 embedding、中文问题、reranker 真实结果和输入截断 | 此模型和此评测集上的语义结果 |
| 回归 | 第十二课导入/幂等/发布/删除、第十一课上下文预算 | 与既有功能的衔接 |
| 页面与截图 | 每个按钮、反复切换、空/错/加载态、图点不丢失 | 实际浏览器展示与交互 |

资料、SQL fixture 和测试报告不包含凭据。最终记录准确的测试数、失败数、skip 数、数据库版本、pgvector 版本、模型身份、执行时间、截图路径与未覆盖项；不能凭“代码写完”标记全部通过。

提交建议按检索契约、PG/关键词适配、融合/重排/预算、评测、前端、课程和图谱分别提交并推送。第十四课后续任务包在本课实现时提供，本任务包不提前声称其已经交付。

## 11. 面试复盘

完成后用本项目的真实报告回答：

1. 为什么向量检索可能漏掉错误码？关键词检索又可能漏掉什么？
2. 为什么不用向量距离直接加关键词分数？RRF 的 rankConstant 怎样影响排名？
3. 重排能修复召回缺失吗？候选数、延迟、费用怎样取舍？
4. 查询改写改变了否定词怎么办？如何证明没有丢掉原问题？
5. 两个模型维度相同为什么仍不能混用向量？升级 Embedding 如何迁移？
6. 过滤后不足 TopK 怎么处理？为什么不能拿未授权块补满？
7. 检索期间资料更新/删除了怎么办？外部重排前何时检查权限？
8. Recall@K 提升而回答没改善，可能是哪一层出问题？
9. 什么证据分别支持“PG 查询正确”“语义效果改善”“页面可用”？
10. 给出一个失败样本，说明你如何凭评测与 trace 改善，而不是凭感觉调参数。

面试陈述模板：问题场景 → 固定资料与标签 → 基线 → 方案与预算 → 自动测试/真实 PG/模型/截图证据 → 指标变化与失败样本 → 仍未覆盖的生产边界。没有测到的数字不填写。
