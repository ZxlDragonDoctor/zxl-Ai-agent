# 第十四课：引用、拒答与长期记忆

状态：**完整六单元学习任务包，工程已实现并完成功能验证；原始真实judge质量门槛未过，边界单列**。实施映射与验证边界见[实现记录](14-implementation.md)。日期：2026-10-24。完成任务包阅读、工程实现与个人独立掌握分别记录。

本课面向能编写 Spring Boot 接口、正在学习 Agent 的开发者。沿用企业知识库与工单助手，把第十三课的候选资料变成有出处的回答，再建立经过用户确认的事实记忆。六个单元组成一个完整功能批次，前端由助手实现，学习重点是 Java 契约、执行控制与业务边界。

## 1. 先理解：资料命中、引用有效和结论正确是三件事

检索返回“VPN 809 排查手册”，仅说明找到候选。模型写出 `[E1]`，还需要检查 E1 是否来自本次允许访问的证据、版本是否有效，以及原文是否支持具体结论。例如手册写“检查网络连通性”，不能据此回答“管理员已经重置了你的账号”。

| 概念 | 含义 | Spring Boot 类比 |
| --- | --- | --- |
| 证据快照 | 本次回答实际使用的文档版本、块与原文范围 | 经过授权和版本检查的只读 DTO |
| 引用有效性 | 引用 ID 能解析到本次证据和准确位置 | 校验外键与资源归属 |
| 可支持性 | 一条业务结论确实由引用内容支持 | DTO 合法之外的领域规则校验 |
| 拒答/澄清 | 资料不足时限制结论、询问必要信息 | 返回明确业务状态而非伪造成功 |
| 短期上下文 | 本次请求和当前会话需要的历史 | 有预算的请求组装 |
| 长期事实记忆 | 跨会话、经确认且可管理的用户事实 | 带来源、租户与生命周期的业务记录 |

```text
可信身份 + 原问题 → 第十三课检索 → 第十一课预算 → 服务器签发证据编号
  → 模型生成结论与引用 → 引用校验 + 支持性判断 + 最终有效性检查
  → 回答 / 部分回答 / 澄清 / 无依据拒答 / 明确服务失败

用户明确提供事实 → 提取待确认项 → 用户确认 → 持久化事实记忆
  → 受限召回 → 更正 / 到期 / 删除 → 后续调用不再使用失效事实
```

知识库用于回答制度、手册等资料问题，用户记忆用于个性化上下文。模型推测和模型自己的历史回答不能自动成为用户事实；记忆中的偏好也不能覆盖当前企业制度。

## 3. 单元一：签发证据编号并校验引用

### 概念

模型只能选择服务器交给它的证据编号。来源文档中的文本、链接和指令都是数据；不允许它们替换系统规则或自行声明权限。

### 实践任务

1. 在本次检索结果有效性检查后，为允许进入上下文的证据分配 `E1…En`，保留 request/trace、documentId、revisionId、chunkId、来源标题、UTF-16 范围/行号、实际送入模型的文本及内容摘要。编号只在当前回答快照内有效，不能跨请求复用。
2. 定义结构化回答 DTO：业务结论列表、每条结论的 evidenceIds、回答状态、缺失信息与拒答原因。纯聊天无需强制资料引用；声明来自知识库的业务事实必须经过本课规则。
3. 验证未知/重复编号、无引用的事实结论、空文本、无效坐标、过长输出与格式错误。引用的原文区间必须落在该版本真实文本中，不能让模型生成任意路径或 URL 作为可信来源。
4. 证据截断时保留真实子区间及标记，不能把未送给模型的完整块假装成它已读过的证据。引用快照和渲染文本使用同一映射。
5. 返回前检查当前权限与资料有效性。文档被删或切换版本时，按明确政策标记失效并停止使用，最多有界重检索/重生成一次；不能展示失效资料或无限重试。

**交付与验收：** 证据和回答契约、编号映射、原文解析接口与测试。未知 ID、其他请求的 E1、越界引用、删除竞态均不能作为有效引用通过。

## 4. 单元二：逐条判断结论是否被证据支持

### 概念

“有引用”可以由程序校验，“引用真的支持结论”还需要语义判断。模型评判可能出错，必须用固定人工标注案例校准；不把一个置信分数当作真值。

### 实践任务

1. 将回答拆成可核对的业务结论；限定每条长度与引用数。用“检查连通性”和“管理员已重置密码”等相近业务案例，标注 supported、contradicted、insufficient 与理由。
2. 先用确定规则核对证据归属、数值/日期/错误码、版本和引用存在性。再定义可替换的支持性检查端口，确定性替身用于控制流测试，真实模型或人工用于语义验收。
3. 对比只检查引用 ID 与检查支持性的差异；覆盖只支持半句话、多证据组合、条件遗漏、否定翻转、旧版本冲突和资料内提示注入。
4. 评判器只接收问题、结论和当前允许证据，输出有限枚举与理由；拒绝新增证据、越权数据和不合法结果。把判定过程视为可审计业务结果，不展示模型私有思考链。
5. 校验失败时允许有界修正一次，否则移除不支持的结论并明确部分回答/拒答。将调用数、超时和修正纳入共享 deadline；检查器服务失败单独返回失败或明确受限状态，不能当成“证据已证实”。

**交付与验收：** 人工标注集、规则用例、替身故障测试和真实评判对照报告。报告准确区分引用合法率与结论支持率；未运行真实评判时不声称语义通过。

## 5. 单元三：证据不足时澄清、部分回答或拒答

### 概念

无命中、命中了无关资料、资料彼此冲突和检索服务不可用是不同状态。只有明确原因，用户才知道应该补充条件、更新资料还是稍后重试。

### 实践任务

1. 定义策略状态，如 ANSWERED、PARTIAL、NEEDS_CLARIFICATION、INSUFFICIENT_EVIDENCE、SERVICE_FAILURE，并映射前端可读说明；状态名为建议，实现后以最终契约为准。
2. 缺少错误码/产品版本时问一条有必要的澄清问题；能够回答的部分逐条引用，其余明确说明缺少何种资料。不要用未经校准的统一相似度阈值决定所有拒答。
3. 区分权限排除后的零候选与无此资料，不泄露其他租户文档是否存在。对知识库之外的问题说明当前回答范围，不编造制度、工单状态或执行结果。
4. 处理冲突版本、过期手册、证据不足和全部检索通道失败。保留错误原因和 traceId，避免把失败伪装成成功查询但无答案。
5. 加入一个完整业务案例：VPN 809 有依据回答 → 未提供错误码时澄清 → 无资料问题拒答 → 检索故障明确报错 → 恢复后再次查询。

**交付与验收：** 状态表、策略测试、含无答案与可回答问题的固定评测集。分别统计错误回答和不必要拒答，不能靠“全部拒答”获得质量通过。

## 6. 单元四：区分短期上下文与长期事实记忆

### 概念

“本次工单涉及打印机”通常是任务临时信息；“我偏好中文回复”可以是用户确认后的持久偏好。“我猜用户是管理员”是模型推断，不能提升为事实或权限。

### 实践任务

1. 建立信息分类：当前任务参数、会话历史、知识证据、待确认事实、已确认记忆。明确每类来源、有效期和用途。
2. 把第十一课上下文组装扩展为独立预算槽：系统规则、当前问题、确认记忆、知识证据、历史。对记忆数量和字符/token 设上限，记录实际选择与丢弃原因。
3. 只在可信 user/tenant 范围查询已确认且未过期、未删除的事实，调用前重新检查。模型和请求参数不得自行扩大用户范围；记忆不能授予工具权限。
4. 明确冲突顺序：当前明确指令可临时覆盖个人偏好；制度类回答以当前有效知识为依据；持久事实冲突须更正确认，不由模型静默覆盖。
5. 演示同一会话的历史恢复、换会话的已确认偏好召回、另一个演示用户无法召回以及预算裁剪。不能以聊天记录里出现过昵称证明持久事实服务通过。

**交付与验收：** 分类与预算决策说明、上下文快照测试、跨会话和跨用户正反向测试。保留原个人学习状态与笔记，演示只使用合成资料。

## 7. 单元五：事实提取、确认、更正、TTL 与删除

### 概念

提取器提出“可能记住什么”，用户决定是否保存，应用负责可信归属与生命周期。数据库记录与索引/缓存的可见性必须一致，否则点击删除后仍可能在回答中出现旧事实。

### 实践任务

1. 设计最小记录：memoryId、tenantId、userId、factKey/value、原始消息/会话来源、提取版本、PENDING/CONFIRMED 等状态、version、createdAt、expiresAt、deletedAt。时间使用统一时钟，TTL 边界写清楚。
2. 提取仅产生待确认候选；页面显示原话与提议事实，提供确认/拒绝。禁止默认保存密码、令牌、权限断言和从模型回答中推断的事实；不要把敏感正文写到诊断日志。
3. 确认时重新校验身份、候选版本和有效期，使用事务与条件更新。重复确认幂等，过期/已删候选不能复活。并发更正返回可解释冲突，不能最后写入无条件覆盖。
4. 已确认事实支持更正并保留必要来源，旧值立即退出召回；TTL 到期以查询过滤即时生效，清理任务晚运行也不能继续使用过期值。
5. 删除同时取消待确认候选并阻止重新发布；若实现向量或缓存，写出清理/失效与重试策略，并验证晚到任务不会复活记录。区分软删除、业务不可见与物理清理，不声称未经验证的彻底擦除。
6. 使用真实 PG 验证迁移、事务回滚、跨用户隔离、重复确认、更正竞争、TTL 边界、删除竞态和应用重启后状态。PG 不可用时明确阻塞，不回退内存后算主线通过。

**交付与验收：** 数据模型、迁移、受限管理接口、真实 PG 集成测试与重启证据。数据库版本沿用第十二课已固定的 PostgreSQL 16.15 + pgvector 0.8.6，具体 schema/API 在实施记录中填写；本任务包不声称已建表或已实现向量记忆。

## 8. 单元六：评估回答与逐按钮页面验收

### 概念与指标

| 指标 | 本课约定 |
| --- | --- |
| 引用有效率 | 有效且可解析的引用次数 / 全部输出引用次数；无引用单列 |
| 支持率 | 人工确认受证据支持的业务结论数 / 已核对业务结论数 |
| 证据覆盖率 | 获得有效支持引用的需引用结论数 / 所有需引用结论数 |
| 无依据错误回答率 | 应拒答组中出现无依据实质回答的问题数 / 应拒答问题数 |
| 不必要拒答率 | 可回答组中被无依据拒答的问题数 / 可回答问题数 |
| 记忆正确性 | 确认、隔离、更正、到期、删除的期望与实际逐项核对 |

分母为 0 时报告未定义，不能填成 100%。固定资料/问题/人工标签版本、模型、提示词、K、预算与拆句规则。开发集与留出集分开；先明确门槛再运行留出集，不能承诺任意模型绝对零缺陷。

### 实践任务

1. 建立包含可回答、部分支持、矛盾、无答案、错误引用、越权资料、注入和记忆冲突的合成案例集。保存原问题、证据快照、原始输出、校验结果、最终状态与人工理由。
2. 分别验证确定规则、服务故障替身、真实 PG、真实模型、端到端页面；报告实际通过/失败/skip 数与命令。规则测试不能代替支持性语义判断，构建不能代替浏览器点击。
3. 回归第十一课预算、第十二课导入/发布/删除、第十三课检索和统一会话 Provider 路径；新增逻辑先补失败用例后修复重跑。
4. 复用统一对话的真实证据卡与事实管理入口，记录用户可见状态和业务结果。截图覆盖连续操作、重复点击和视图切换；发现问题修复后重跑相关流程。

### 逐按钮截图清单

| 操作 | 预期与截图要点 |
| --- | --- |
| 选择 Agent 类型、新建会话、发送有依据问题 | 同一聊天页面出现真实回答状态、引用编号和来源卡 |
| 点击不同引用、展开/关闭来源、再次打开 | 正确版本/原文范围与结论对应，阅读窗内容不会串位 |
| 连续发送澄清、无资料、部分支持问题 | 状态不同且含原因；上次来源不会残留为本次依据 |
| 触发模型/检索/校验故障后重试 | 错误与无答案可区分，恢复后可继续操作 |
| 提交事实、拒绝、重新提议、确认、重复确认 | 未确认不能召回，确认幂等，来源和归属可见 |
| 更正、取消更正、并发冲突后刷新 | 展示当前版本；旧值不参与后续回答 |
| TTL 到期、删除后连续查询、换会话与应用重启 | 失效事实不再进入上下文；历史文本是否仍保留单独说明 |
| 切换演示用户/租户后查询 | 无其他用户事实或来源泄露；标注固定演示身份边界 |
| `/learning` 课次筛选、1/2跳、全图、2D/3D、节点阅读、中英文 | 第十四课状态与最终验收记录一致，文字/点/线完整，切换后阅读卡一致 |

每项记录操作、预期、实际、截图路径、时间与错误；环境不支持的项目标未验收，不用旧图替代。本地测试产生的进度、笔记与资料变更要恢复；只提交合成样例和可公开证据，不提交凭据或运行数据库。

**交付与验收：** 固定评测集、分层测试结果、真实调用报告、逐按钮截图索引、已知限制、更新后的课程和图谱。按回答契约/校验、记忆持久化、前端、课程文档分别提交并推送；不自动标记个人“已掌握”。

## 9. 集中验收与独立练习

本批完成应能演示：有效资料回答并定位原文 → 无依据时明确拒答/澄清 → 用户确认偏好 → 换会话召回 → 更正 → 到期或删除后不再召回。必须同时具备自动化、真实数据库、真实模型和页面证据，缺失部分写清楚；任务包发布只代表任务完整。

独立练习：增加“回复语言”事实类型，说明哪些内容允许提取、如何确认、何时覆盖、更正冲突怎样返回；为一条格式正确但不支持结论的引用写失败案例，并解释由哪层拦截。

面试复盘：模型生成 E1 为何不可信？检索分数为何不能直接作为答案置信度？全部拒答为什么不是质量优秀？会话历史与事实记忆如何区分？删除怎样阻止缓存、向量与晚到任务复活？没有完整登录时，固定演示身份能验证什么、不能证明什么？
