# 第24课：数据库备份与恢复验收

生成dump不等于具备恢复能力。本项目把归档字节、目标身份、数据库结构、业务数据、权限和应用读回分别验证，恢复始终指向另一PG容器的新库，不覆盖源库。

## 备份边界

pg_dump custom格式通过子进程文件描述符直接写入新文件，避免PowerShell文本重定向破坏二进制。manifest记录源容器固定ID和SHA256；恢复比较目标固定ID，防止名称/ID别名绕过。摘要只证明字节一致，不证明归档可信，不能恢复不可信SQL归档。

恢复先确认目标库不存在，再创建新库，pg_restore使用单事务和exit-on-error，保留owner/ACL，不使用clean/drop/no-owner。失败保留新库和失败记录供检查，不自动重试或删库。

## 数据之外的依赖

数据库dump不包含全局角色密码、应用配置、会话文件卷或浏览器学习进度。目标先建立所需角色名及新密码，不能预建lesson12/17以免与归档创建schema冲突。应用代码、迁移版本和pgvector库必须配对。

目标新库可能带回默认PUBLIC数据库权限，因此恢复后明确撤销CREATE/TEMP，并重新验证运行身份。旧登录会话在开放应用前撤销，但保留会话行供审计关联；验证必须用新登录。此处的会话撤销不是恢复进行中的Agent任务。

## 怎样验收

本次源库先导入隔离演练文档，用真实Embedding生成1024维向量，再备份。恢复后比较12张稳定业务表的行数及有序JSON逻辑摘要，确认报告、预算和知识数据一致；新登录读回原completed报告，真实检索命中恢复文档。摘要比较排除了登录会话及不断变化的权限审计，不能宣称逐字节克隆整个数据库。

恢复后独立Compose只有PG及业务服务，不运行初始化、迁移、授权任务；三角色显式validate连接RECOVERY_DB_NAME。原运行组和恢复组隔离，重启后再次读取报告与检索，未重新调用对话模型。源端演练文档通过正常API删除，审计与版本记录按业务策略保留。

## 面试复盘

为什么备份文件存在不能证明可恢复？为什么no-owner可能改变权限模型？为什么不应恢复旧登录态继续演示？逻辑dump没有覆盖WAL/PITR、文件卷和浏览器进度时，怎样诚实描述恢复范围？

仍待：TLS、应用回滚兼容性、完整双租户审批验收、持续交付与容量基线。备份恢复这一单元通过，不等于28课全部完成。

## 会话文件与 PostgreSQL 成对恢复（新增验收）

正式对话采用两类存储：`FileConversationRepository` 写入 UUID.json，`lesson17.resource_owner` 保存归属。只恢复文件可能因缺失归属而看不到；只恢复数据库则缺失历史消息。两者没有跨资源事务，因此先确认测试运行已结束，再停止 main/worker/mcp/frontend，PG保持可用，在同一停写窗口连续备份数据库和会话卷。该窗口依赖操作者禁止其他写入，不声称在线一致性快照。

`volume-backup.mjs` 仅接受普通 local named volume，运行中挂载的卷拒绝备份。恢复仅新建卷，不覆盖已有目标。先解析有界 USTAR、核对摘要，再解包：必须含可写的UID/GID10001根目录，只接受平面UUID.json，拒绝链接、路径穿越、临时文件、重复名称及不匹配的JSON ID。摘要校验不能认证归档来源；必须使用可信归档和固定helper镜像。

实际演练恢复到独立5218运行组：选定12表逻辑指纹一致；两条消息和一次已完成运行的API详情一致；卷文件SHA256及10001属主一致；恢复前撤销10条旧登录会话，新登录选择历史、查看消息、展开执行记录、切换语言、刷新后重选均可用。恢复后新建并保存一次对话成功，再仅删除该临时对话。确定性证据不足拒答用于验证存储，不把它称为新的真实回答模型测试。
