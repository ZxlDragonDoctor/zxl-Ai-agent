# 第十七课：PostgreSQL 连接中断与恢复

权限检查依赖 PostgreSQL。连接中断时，正式入口无法确认会话和执行权限，应拒绝请求。恢复连接后，重新打开原会话确认是否曾开始运行，再用新请求验证完整业务链路。

本次使用 `ceffcb5` 的隔离环境，通过专用 TCP 转发访问真实 PostgreSQL 16.15。关闭应用的既有连接并拒绝新连接，避免干扰其他应用。已登录浏览器点击发送，收到 HTTP 503 和 `AUTHORITY_UNAVAILABLE`。恢复转发后，同一原会话读取返回 200，持久化运行数为零。

恢复后的第一次真实请求完成 MCP 知识工具调用。最终模型回答在剩余 15.229 秒内未结束，持久化为超时，页面无草稿。另开一轮较短的请求后，qwen-plus 完成回答，生成仅引用乙租户资料的待审批草稿，运行持久化为 `completed`。

练习时分别观察 HTTP 状态、持久化运行数、MCP 工具事件与最终草稿。可以据此区分入口拒绝、连接恢复、模型耗时和业务完成。本轮注入的故障发生在提交前。数据库进程重启另见归档课内实验，在途断库仍待独立验收。
