## 实现结果

| 能力 | 工程落点 | 已取得证据 |
| --- | --- | --- |
| 明确错误分类 | `RetryFailure` | 永久错误与未知异常均不重试；已知瞬态失败才进入有限循环 |
| 有限退避 | `RetryPolicy`、`RetryExecutor` | 尝试次数封顶、指数退避上限、full jitter、剩余预算不足停止 |
| 总预算与取消 | 复用第七课 `ExecutionControl` | 退避期间取消/到期后不发起下一次；中断等待保留中断标记 |
| 操作身份与指纹 | `TicketCommand`、`OperationLedger` | 同 ID/同参数返回原结果，同 ID/异参数明确冲突 |
| 本地工单原子写入 | `InMemoryTicketGateway` | 30 个并发重复调用返回同一张工单；容量满不删除既有去重结果 |
| 响应丢失 | `TicketService`、可控适配器 | 写入成功后第一次响应丢失；第二次同 ID 重试返回原 ticket，次数 2、工单数 1 |
| 失败保留 | `OperationLedger` | 永久失败可重放；未知异常保留 `OPERATION_UNCERTAIN` 防止无依据重复写入 |
| HTTP 演示 | `LearningTicketController` | MockMvc 验证普通重放、列表数量、409 参数冲突、输入与预算错误 |

默认工单实验策略为 3 次尝试、100 毫秒基础退避、1000 毫秒退避上限、5 秒请求总预算（允许 1–30000 毫秒），账本容量 1000。该容量和时间用于教学边界，未做吞吐或生产容量承诺。

## 当前边界

- `lesson8-demo` profile 才开启 `/ai/learning/tickets`；这是本地单用户实验入口。没有自动注册 Agent 写入工具，没有接入业务审批、认证或租户隔离。
- 账本和工单只在 JVM 内存中，互斥锁只保护当前进程。重启清空状态，多个实例间不共享去重结果；下一课才实施数据库和恢复。
- 锁内只执行短暂本地 Map 写入。不能将这个临界区实现替换成远程 POST 后宣称原子；跨系统写入需要下游幂等/查询、结果核对或补偿。
- `RetryExecutor` 仅重试显式分类的安全操作边界，不改写模型 SDK 或整个 Agent 工作流的重试策略。已在执行的阻塞调用仍依赖适配器的有限超时/取消能力。
- 取消不能撤销先前已提交的工单；必须保留操作 ID 核对结果。未知异常保留不确定状态，并不自动认为“没写成功”。
- 账本不自动淘汰，以免忘记旧操作后重复写入；满容量拒绝新键，既有键仍可重放。生产保留/清理策略尚未实现。
- 本次完成源码实现与指定受控测试；没有真实模型、真实外部写入、跨进程恢复、生产安全或压力验收。个人掌握状态不由这些检查自动更新。

## 面试可用的证据表达

“我实现了一个有限重试的本地工单操作：错误显式分类，退避包含随机抖动，所有尝试共享总预算。并发请求由操作 ID 和参数摘要判重。测试在服务端写入成功后丢掉第一次响应，客户端用同 ID 再试时返回原工单；同时验证参数冲突、未知结果、取消和容量。当前边界是单 JVM，数据库持久化与租约恢复是下一阶段，不能保证跨系统所有动作恰好执行一次。”
