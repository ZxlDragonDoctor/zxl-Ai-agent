## 默认演示容量

`RuntimeSettings` 提供以下默认值，并支持 `agent.runtime.*` 配置覆盖：

| 资源 | 默认值 |
| --- | ---: |
| 单进程同时协调运行 / 运行排队 | 2 / 8 |
| 运行登记表 | 200 条，结束且清理完成后保留 10 分钟 |
| 工作线程 / 等待队列 | 4 / 16 |
| 同时进行的模型调用 | 3 |
| 消息总线线程 / 执行队列 | 8 / 256 |
| 消息队列 / 事件队列 | 256 / 512 |
| Agent 与模型许可排队上限 | 30 秒 |
| 运行总预算默认 / 最大 | 90 / 180 秒 |
| 单次 HTTP 连接 / 请求超时 | 5 / 30 秒 |

这些值用于本地演示和边界保护，不代表容量测试结论或生产建议。达到任务/工作队列上限时显式拒绝；事件队列是尽力而为的观察通道，队列满会计数并记录警告。消息消费者在执行池满时退回队列线程执行以提供背压，不会另开无限线程。

## 语义与边界

- `POST /ai/multiagent/runs` 返回 `executionId`；`GET /ai/multiagent/runs/{id}` 读取当前运行；`POST /ai/multiagent/runs/{id}/cancel` 返回取消回执。登记表是 JVM 内存结构，重启后不可恢复。
- 当前接口属于本地单用户演示。知道 `executionId` 不构成生产授权；身份、租户和运行所有权后续补齐。
- 对不可协作中断的同步模型调用，取消先收敛业务 outcome；实际调用直到有限 HTTP 请求超时或真实返回前仍占有模型许可与 Agent。不能把 `CompletableFuture.cancel(true)` 当成底层 HTTP 已停止的证明。
- SSE 断连仅停止向该连接发送事件。服务端执行仍可查询；只有显式取消接口才改变运行控制状态。
- 任务结束后仍应分别核对 run 状态、任务终态、模型/工作占用与清理中数量，不能仅看进度比例。
- 本次完成编译和指定自动化验收，未做真实模型压测、跨进程恢复、分布式协调或生产负载容量承诺。
