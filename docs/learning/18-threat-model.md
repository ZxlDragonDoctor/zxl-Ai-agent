# 第十八课：内容来源与权限边界

对 Spring Boot 开发者，可以把模型的工具建议当成一次外部 API 请求。服务端先确定调用者、工具集合和预算，再检查建议里的字段。知识原文可以支持业务结论，它的来源和内容都不能改变调用者身份或扩大工具权限。

| 内容来源 | 谁能影响 | 允许用途 | 控制点与待验证边界 |
| --- | --- | --- | --- |
| 用户问题 | 当前会话的使用者 | 表达业务意图，生成搜索词 | `ResearchRunner` 验证工具名、参数及预算。身份来自服务端会话。 |
| 对话历史和事实记忆 | 用户消息、Agent 输出、用户确认的偏好 | 恢复对话或调整回答样式 | `ConversationContextWindow` 管理历史，`MemoryAnswerContext` 投影偏好。历史工具输出仍属于输入数据。 |
| 知识标题、正文和检索命中 | 具备文档维护权限的使用者 | 查找依据和展示引用 | `McpEvidenceVerifier` 复核当前版本、片段和位置，`StreamingResearchModel` 控制最终回答可见的证据字段。正文仍可能诱导模型。 |
| MCP 工具描述与参数定义 | MCP 服务 | 匹配已审查的工具契约 | 正式入口固定版本和摘要。运行时工具发现内容需要与契约匹配。 |
| MCP 结果与错误 | MCP 服务或它检索的资料 | 提供候选证据、诊断工具失败 | 工具事件和最终模型是不同出口。完整工具事件当前早于原文复核发布，脱敏及可见字段仍需补齐。 |
| 附件名称、正文与产物 | 上传者及处理程序 | 确定本次任务的授权输入和摘录 | 文件、路径与网络隔离仍待实测。宿主旧工具不应作为隔离实验的实现。 |
| Skill 定义 | 服务器注册表和部署者 | 固定步骤、版本和工具范围 | `SkillRegistry` 固定定义。用户只请求已发布的版本，正文中自称新版规则没有控制作用。 |

攻击演练只使用普通请求、获准维护的合成知识或测试 MCP 响应。工具调用次数、跨租户标记、外发监听器和文件哨兵用于观察行为。模型答错属于答案质量失败，即使没有产生越权调用也要单独记录。

分开检查三条不变量。执行器只能调用服务端允许的工具。用户、资料和工具结果无法改变身份或政策。外部正文不得直接变成命令、URL、SQL、文件路径或审批结果。
