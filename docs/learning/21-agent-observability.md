# 第二十一课：日志、指标与分布式追踪

工程问题：用户说一次运行很慢，只能提供界面上的运行 ID。如何判断时间耗在排队、模型首包、MCP 调用，还是取消后的资源清理？

日志回答某件事发生了什么；指标回答这类事多久、多少；Trace 把同一次运行跨进程的活动串起来。以运行 ID 查日志或 Trace 属性；指标按有限的组件、操作和结果聚合，禁止把运行 ID、用户 ID、原始提示词用作指标标签。

1. 从 `AgentObserver`、正式运行入口和 `DashScopeAgentStreamer` 找出现有日志和计时。定义运行、任务、模型和 MCP 四类 span 及父子关系，在工作线程和远程调用边界传播上下文。验证两个同时运行的请求不会串线。
2. 定义总耗时、模型首包、工具耗时和清理耗时的测量边界。模型提供真实 usage 时才记录 token；缺失时保留缺失状态，并且把实际计数和估算分开。
3. 添加日志和指标的敏感字段测试。分别触发模型超时与工具失败，从工作台复制运行 ID 找到对应失败 span，并核对取消、资源清理、用户可见终态的区别。
4. 验收时分别记录自动回归、真实模型与 MCP、遥测导出端，以及页面操作截图。没有可用的遥测接收端时，只能证明本地记录和上下文传播。

面试练习：平均耗时没有变，为什么 p95 会翻倍？你会用什么证据判断是模型变慢还是队列积压？

## 模型调用的首批落点

`ExecutionRuntime.modelCall` 分别记录等待模型许可和许可到归还的时间，并用固定的结果类别标记二者。运行 ID 和任务 ID 进入结构化日志。模型传输日志另外记录首帧、授权检查和流结束状态。在调用线程内设置相关 ID，调用退出时恢复线程原来的 MDC，避免下一项任务继承本次 ID。

许可等待结束只说明拿到了本地容量。传输首帧计时从构造 HTTP 流开始，包含本地授权和网络开销。任务 ID 来自模型时可能是自由文本，日志仅接受可解析为 UUID 的值。

用 `-Dagent.observability.jmx-enabled=true` 启用本地 JMX 指标导出。用 JConsole 连接 JVM，在 MBeans 中找到 `com.zxl.agent:type=ModelMetrics` 并读取 `Snapshot`。每条记录只含固定计时器名、结果标签、次数、总耗时和近期最大值。均值可用总耗时除以次数。此快照没有直方图，无法从中计算 p95。

正式 Research Agent 已记录知识 MCP 工具完成或失败时的网关耗时。日志可用运行 ID 找到同一次调用，用调用摘要关联工具记录。工具名称使用固定协议名。参数、返回正文和原始模型调用 ID 均不进入这份日志。

[真实运行截图与耗时记录](../images/lesson21-model-2026-11-15/README.md) · [第 22 课学习任务](22-agent-evaluation.md)

用 1 秒预算提交正式运行，页面会显示失败，事件回放记录 `RUN_DEADLINE_EXCEEDED`。终态日志在保存事务提交后记录结果、是否超时及当时持有的任务和模型许可数。许可数是终态时刻的快照，清理完成时间需要单独测量。并行回归验证了运行 ID 不会串线，计时器只有结果标签。 [超时逐状态截图](../images/lesson21-timeout-2026-11-15/README.md)

DashScope 的流式用量帧可能没有任何回答片段。解析器先读取用量，再判断该帧有无输出。Spring AI 响应元数据和传输日志保留输入、输出及总 token 数。服务端没有返回的字段保留为 `null`，明确返回的零照常保留。 [百炼流式协议](https://www.alibabacloud.com/help/en/model-studio/stream)
