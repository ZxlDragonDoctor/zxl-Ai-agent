# 第二十一课：日志、指标与分布式追踪

工程问题：用户说一次运行很慢，只能提供界面上的运行 ID。如何判断时间耗在排队、模型首包、MCP 调用，还是取消后的资源清理？

日志回答某件事发生了什么；指标回答这类事多久、多少；Trace 把同一次运行跨进程的活动串起来。以运行 ID 查日志或 Trace 属性；指标按有限的组件、操作和结果聚合，禁止把运行 ID、用户 ID、原始提示词用作指标标签。

1. 从 `AgentObserver`、正式运行入口和 `DashScopeAgentStreamer` 找出现有日志和计时。定义运行、任务、模型和 MCP 四类 span 及父子关系，在工作线程和远程调用边界传播上下文。验证两个同时运行的请求不会串线。
2. 定义总耗时、模型首包、工具耗时和清理耗时的测量边界。模型提供真实 usage 时才记录 token；缺失时保留缺失状态，并且把实际计数和估算分开。
3. 添加日志和指标的敏感字段测试。分别触发模型超时与工具失败，从工作台复制运行 ID 找到对应失败 span，并核对取消、资源清理、用户可见终态的区别。
4. 验收时分别记录自动回归、真实模型与 MCP、遥测导出端，以及页面操作截图。没有可用的遥测接收端时，只能证明本地记录和上下文传播。

面试练习：平均耗时没有变，为什么 p95 会翻倍？你会用什么证据判断是模型变慢还是队列积压？
