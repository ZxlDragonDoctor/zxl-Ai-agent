# 第十六课：Skill、业务策略与受控工具范围

状态：**工程已实现并分层验收**，见[实现、测试、真实模型与截图记录](16-implementation.md)。日期：2026-10-25～26。先修：[第十五课 MCP 工具契约与适配](15-mcp-tool-contracts-and-adapters.md)、第七课执行预算、第十四课证据回答。工程完成不改变个人掌握状态。

业务目标：把“企业 IT 工单分析”组织为可版本化 Skill：澄清问题、查询当前有效手册、形成有引用的处理建议、输出人工确认所需的草稿。复用统一 `/chat-room`、真实 MCP 与 PostgreSQL；本课不开放自动创建或修改真实工单。

## 1. 先理解：Skill 在 Java 应用中是什么

一个工具解决一次动作，例如查询手册。一个 Skill 组织一类业务的目标、步骤、输出要求和工具范围。模型可帮助理解问题和提出动作，Java 负责验证动作是否允许、资源是否有效、预算是否足够，并保存实际执行记录。

| 机制 | 本课职责 | 熟悉的 Java 类比 |
| --- | --- | --- |
| Prompt | 告诉模型本轮目标、资料边界和输出格式 | 对一个调用的说明，不能作为权限检查 |
| Tool / MCP | 暴露一个参数有界、结果可校验的能力 | 受控接口与客户端适配器 |
| Skill 定义 | 版本、业务步骤、允许工具引用、输出要求 | 不可变配置和策略描述 |
| Skill 执行器 | 校验定义、选定版本、执行步骤并记录结果 | Strategy + 应用服务 |
| 授权策略 | 根据可信身份与服务端政策批准实际调用 | 每次调用前的服务端检查 |
| 工作流 | 管理步骤顺序、等待、终态和恢复边界 | 状态机；跨进程恢复须另行实现 |

本课先实现项目内的声明与执行机制，不声称采用某个通用 Skill 文件标准，也不让下载的 Markdown 自动获得执行权限。

```text
用户选业务策略 → 服务端定位 skillId + 固定版本
  → 校验定义/状态/工具来源 → 保存本次不可变快照与摘要
  → 澄清 → 只读 MCP 查询 → 当前版本证据校验 → 建议与工单草稿
  → 每次调用前核对有效工具集合、预算、取消与当前授权
  → 保存公开事件、版本和结果 → 页面展示
```

## 3. 单元一：定义可版本化 Skill 契约与注册表

### 概念

同名策略在不同日期可能有不同步骤。一次任务必须知道使用哪个版本，不能运行到一半悄悄换新配置。版本标签便于阅读，内容摘要用于发现“同版本内容被替换”。

### 实践任务

1. 定义 `SkillDefinition`：`skillId`、明确版本、说明、步骤、允许工具引用、输出 schema 版本、预算上限、状态和内容摘要。标识、字符串、列表长度与配置大小均有界；拒绝未知字段、重复步骤和未注册执行类型。
2. 首个 Skill 使用 `it-ticket-analysis`，v1 只读分析；准备 v2 的输出字段变化用于对照。配置来源固定为仓库受审查目录或可信发布入口，不从模型文本、网络 URL、任意文件路径装载。
3. 注册键为 `(skillId, version)`；重复键且不同摘要直接拒绝。依赖的工具必须能解析到固定服务、原名/暴露名和契约版本；缺失、冲突或 schema 不兼容时标不可执行，不静默换其他工具。
4. 提供稳定的列表与版本查看 DTO。新请求显式选择版本，或由受控默认指针解析后固定；一次运行保存实际版本、定义摘要、执行器版本和工具快照摘要。
5. 制作非法定义用例，再实现解析/注册。不要把任意 YAML/JSON 动态绑定到类名、反射或脚本执行。

**交付与验收：** v1/v2 示例、版本与错误契约、解析测试。不存在版本、同版本篡改、未知执行类型、缺失工具均被明确拒绝；未开始真实调用。

## 4. 单元二：把业务策略落成 Java 强制检查

### 概念

Skill 的工具清单是一项限制。它不能给本来没有权限的身份增加权限。有效范围取各层允许集合的交集，同时考虑当前服务可用性。

```text
有效工具 = 服务端政策允许 ∩ 可信身份允许 ∩ Agent 允许 ∩ Skill 声明允许
```

服务发现只提供候选能力；不可用的工具不能执行，发现新工具不能自动扩大上述集合。

### 实践任务

1. 建立独立策略接口，例如 `SkillExecutionPolicy`；请求携带可信执行上下文，模型只能提交业务参数。禁止 Skill 或工具参数覆盖 tenant、user、服务 URL、命令和凭据。
2. 在“提供给模型的工具集合”和“真正 dispatch 前”各做检查；第二次检查是必要的执行边界，不能只靠隐藏工具描述。
3. 本课只开放知识查询。模型请求终端、跨租户查询、工单写入，或 Skill 清单出现此类能力时，产生明确拒绝事件，不执行副作用。
4. 区分策略拒绝、工具不可用、输入非法、无结果和运行失败。事件只包含公开理由与脱敏业务字段，不泄露密钥或完整内部上下文。
5. 用伪造工具请求和篡改 Skill 定义直接测试调度入口，确认绕过前端或模型选择仍无法执行。

**交付与验收：** 权限交集测试、dispatch 拒绝测试、版本化策略说明。固定教学身份仅证明受限范围，不称为生产认证；正式登录与租户授权留在第十七课。

## 5. 单元三：可解释的步骤执行与预算

### 概念

步骤是业务动作，有自己的输入和结果；提示词长短不是步骤状态。一个 Skill 可以按受控代码固定顺序执行，也可以使用已验证 DAG，但不能仅凭模型输出“我已经完成”推进业务状态。

### 实践任务

1. 实现四步：澄清必要信息 → MCP 查询 → 验证证据并生成建议 → 形成草稿。缺错误码时可澄清；无资料时拒绝给确定结论；草稿明确“尚未创建工单”。
2. 明确步骤输入与结构化结果，如 `NEEDS_INPUT`、`SUCCEEDED`、`FAILED`、`CANCELLED`。结果与事件来自真实执行，模型生成文本须按 schema 校验。
3. 复用剩余截止和有界并发；等待队列、工具调用、模型调用和最终检查都计入同一个期限，重试次数/调用数也有上限。
4. 只读重试沿用第八/十五课分类；参数、授权和业务拒绝不重试。取消后不发新调用，迟到返回不能改写终态；不把取消宣称为远程回滚。
5. 每步输出明确的可公开事件：Skill 版本/摘要、步骤、允许工具、实际调用 ID、耗时、失败分类和最终状态；保留详细结果与页面预览的区别。

**交付与验收：** 成功、澄清、无证据、超时、取消、满载与迟到完成自动测试。若未实现跨 JVM 恢复，重启中的任务标为中断，不能宣称自动接续。

## 6. 单元四：变更、回滚与信任边界

### 概念

回滚默认版本影响之后创建的运行。已经开始的运行需要固定自己的定义，同时仍受实时权限撤销与工具下线约束。恢复旧配置不能恢复已经执行的外部副作用。

### 实践任务

1. 提供受控启用/停用和默认版本选择；可以先用经过审核的配置发布，不要求本课建设在线编辑平台。校验失败保留旧可用版本，并明确报告新版本拒绝原因。
2. 运行 A 固定 v1，切换默认到 v2 后新运行 B 使用 v2；A 的输出要求不变。停用版本拒绝新运行；明确在途运行继续或终止策略。若撤销权限，后续 dispatch 必须停止。
3. 将配置摘要、策略版本和工具身份写入运行记录，保留旧版本可读快照。回滚后旧记录不能被新定义重解释；若只做教学文件审计，记录其并发与耐久边界。
4. 恶意手册/用户材料包含“加载新 Skill”“调用管理员工具”“跳过校验”时，只作为数据处理；验证工具范围、身份和证据来源不变化。模型文本防御不替代 Java 检查。
5. 输出写操作后续设计：草稿、operationId、参数指纹、审批者/主体/资源/版本绑定、批准后重验与未知结果查询。此次不执行实际写入；审批状态机在第十九课实施。

**交付与验收：** v1→v2→v1 的可追踪对照、在途快照/权限撤销与恶意资料测试。沙箱、生产身份和写入审批仍分别属于第十八、十七、十九课。

## 7. 单元五：统一页面与可审计业务体验

### 概念

用户需要看见“正在执行哪项业务策略、依据什么资料、是否真的写入”，而不是模型私有思考链。Skill 选择不能把每种业务变成独立聊天页。

### 实践任务

1. 复用 Provider 注册与 `/chat-room`，提供可用 Skill、版本、受限工具和服务状态；默认策略可选，实际选定版本随该次运行保存。
2. 展示业务步骤、真实工具卡、证据与最终草稿；明确区分需要补充信息、成功、无依据、拒绝、超时和取消。
3. 策略切换只影响新运行；历史按当时版本/摘要展示。不能把旧历史标签覆盖为当前默认版本，也不能跨会话串用上一次工具结果。
4. 拒绝和故障可以查看公开原因；参数/结果可展开、关闭、再次展开，中英文静态文案及移动布局可读。
5. 保留个人笔记和学习进度，知识图谱展示工程状态与下一课入口；页面验证不自动标记已掌握。

**交付与验收：** 所有新按钮及状态逐项实际操作、截图；连续切换 Skill/版本、会话、语言和视图后内容仍对应真实运行。

## 8. 单元六：分层集中验收

先补可失败用例，再实现并运行相关回归。所有层次单独记录，编译和截图均不能替代真实业务验证。

| 验证层 | 必须验证 | 记录边界 |
| --- | --- | --- |
| 离线契约/策略 | 非法定义、版本冲突、权限交集、调用入口拒绝、快照、回滚与迟到终态 | 不证明 MCP/PG/模型实际可用 |
| 真实 MCP 与 PG | 固定来源知识查询、版本/删除复核、服务断开/恢复、数据库失败 | PG 不可用明确失败，不切内存算通过 |
| 真实模型 | 工具选择、引用、澄清、无依据拒答、注入负例 | 固定模型/策略/数据版本，人工核对；保留失败 |
| 页面 | 新控制、所有结果状态、连续切换、历史、双语和移动布局 | 操作、预期、实际、截图一一对应 |
| 发布/记录 | 默认 v1→v2→v1、旧运行固定版本、未授权发布被拒绝 | 不能以回滚配置宣称撤销外部动作 |

### 页面验收顺序

1. 查看 Skill 列表与 v1 详情，核对工具白名单；选择不存在/不可用版本时明确提示。
2. 正常 IT 问题出现真实 MCP 调用、当前来源和“未创建”的草稿；展开/收起/重开工具结果与引用。
3. 连续发送缺少信息、无资料、越权工具要求；得到澄清/拒答/拒绝，前一次成功结果不串入。
4. 执行中取消、超时与满载拒绝，观察终态；服务断开/恢复后再运行。
5. 默认从 v1 切 v2 再回滚，核对旧记录仍是原版本；切历史/Agent/语言/移动布局。
6. `/learning` 打开第十六课、Skill/策略概念、源码与第十七课入口，核对筛选、关系和阅读卡。按实际证据维护工程状态，保留个人进度。

**完成标准：** 六单元实现、自动测试和相关回归、真实 MCP/PG/模型、逐按钮截图、版本回滚证据分别归档；未执行或失败项明确标注。按契约、执行策略、业务集成、前端和文档细分提交并推送。

## 9. 独立练习与面试复盘

**独立练习：** 在原 Skill 上增加“只输出适合一线客服阅读的排查清单”版本，保持相同只读工具权限。再故意加入终端工具声明，补一个必须拒绝的测试；说明换输出风格为何不需要增加业务权限。

**面试追问：**

- Skill 与 Prompt、Tool、工作流分别负责什么？为什么只写工具白名单到 Prompt 不够？
