# 第 23 课：预算、模型路由与有限降级

第 22 课回答“这次改动表现怎样”，本课回答“允许花多少资源、怎样在约束内执行”。超时能限制等待时间，却不能证明供应商没有继续处理请求，也不能替代用量核算。

## 与 Spring Boot 的联系

将预算账本理解为并发库存预留：只先读余额再调用模型，会让多个并发任务同时看到足额余额。应用必须在同一个数据库事务中锁定账户、检查剩余额度、建立调用预留，然后才允许执行。网络等待放在事务外，避免长期占用数据库锁。

账本使用 token 配额，不能把 token 直接称为人民币费用。供应商返回的 usage、应用本地估算和供应商最终账单是三种证据。缺失的 usage 必须标为未知，不能补写为零。

## 一个完整功能单元

1. 建立租户范围内的预算账户和调用预留。预算和模型选项由可信 Java 策略决定，模型或浏览器不能自行提高额度。
2. 调用前原子占额，限制接受的调用次数；同一调用 ID 重放必须幂等，不同估额不能冒用旧预留。
3. 调用发出后按实际 usage 结算一次。实际用量超过预留时如实记录超额，禁止为维持“余额不负”而篡改观测值；后续调用拒绝继续占额。
4. usage 未知时保留在途或未知预留，仅确定没有发出供应商请求时才释放。服务重建后仍能查询账本，不能因内存清空而恢复满额。
5. 将账本接入真实模型执行入口，排队与取消不能产生重复调用；执行事件显示估额、已返回用量、未知用量和拒绝原因。
6. 增加有限模型路由和降级：只允许部署配置中的模型，限制降级次数；权限拒绝、资料不足、取消与预算耗尽不能触发换模型绕过边界。每次新调用都必须重新预留，不能复用上次已消耗的额度。

## 在本项目中定位代码

- `agent/stream/DashScopeAgentStreamer.java` 已解析供应商 usage；日志或返回元数据存在，不等于预算控制已经接入。
- `multiagent/runtime/ExecutionRuntime.java` 管理容量与截止；这些控制可复用，但当前时间预算不能代替 token 账本。
- `security/SecurityDatabase.java` 提供 PostgreSQL 事务基础；租户复合键与并发锁需要专项验证。
- 第 22 课报告中的受控时钟测试用于机制验证，不能拿其物理耗时推导线上成本或吞吐。

## 首批工程边界

`usage/TokenBudgetLedger.java` 与 V8 迁移已实现账户锁内的原子预留、幂等绑定、结算、未知和未发送释放。`dispatch` 仅首次转换返回 true；重放者不能再次取得发送许可，但这不保证供应商网络调用恰好一次。发送后丢失回执须保留 UNKNOWN，后续人工对账流程仍待实现。

accepted_calls 是预留受理次数，释放未发送请求不会退还这个计数；它不是供应商实际请求数量。租户来自可信服务构造参数，复合键隔离不等于已完成 HTTP 身份授权。本批不开放公共账本接口，不自动为用户建立满额账户。

`TokenBudgetLedgerPgTest` 的真实 PG 专项验证两实例争抢、重放冲突、超额实记、UNKNOWN 保留、调用次数限制及独立数据库对象重建；没有用对象重建冒充操作系统进程或数据库重启验收。真实模型执行接入、模型路由、有限降级、usage 缺失的运行恢复与预算交互页面仍待完成。

## 模型调用接入与有限降级

正式多 Agent 的 planner/code/supervisor 流调用，以及 ScopedResearchFactory 创建的 select/answer 模型调用，现已接入同一可信 actor/run 账户。不同调用与降级尝试使用独立 call ID；后续调用只核对账户策略，不重置已用额度。额度不来自浏览器 context 或模型工具参数。

| 服务端配置 | 默认值与含义 |
| --- | --- |
| agent.usage.enabled | false；默认不启用本批可选控制 |
| agent.usage.run-token-limit | 20000；每个 run 的预留与已知用量约束 |
| agent.usage.run-call-limit | 8；受理次数上限，释放未发送调用不退还次数 |
| agent.usage.call-token-estimate | 4096；每次调用固定估额，尚非上下文精确 token 估算 |
| agent.usage.fallback-model | 未设置；如设置，必须与主模型不同，由部署者选择 |

主模型仍取原有 spring.ai.dashscope.chat.options.model。仅 HTTP 429/503 且没有产生任何输出、没有取消、没有安全或记账错误时，允许一次备用调用。不能从错误消息里猜“503”，不能降级绕过权限拒绝、预算不足或取消。第二次失败直接终止，每次尝试重新预留。主调用没有返回 usage 时，即使备用成功，主调用预留也保守保留 UNKNOWN。

一条真实 qwen-plus 直连验收返回 21 token，PostgreSQL 实际记入 21、在途预留归零，状态 SETTLED。此请求使用独立合成账户和生产 streamer/ledger，不等于已验收完整 HTTP 身份工作流。[真实用量、测试与页面证据](../images/lesson23-usage-2026-11-20/README.md)

随后另用独立测试员工完成认证 HTTP 多 Agent 闭环：规划、Research、实际 MCP 空检索、正确拒答及清理均完成，两笔账本分别结算 1027、842，合计 1869 token，预留归零。实际工具事件确认 SKIPPED_EMPTY_INDEX 且无降级，先前空库修正已在新 Worker 的真实链路验证；这不是跨版本模型质量对照。

当前是每 run 配额，不能限制同租户不断新建 run 的周期总消费。默认关闭，尚未覆盖所有 Love/Manus/独立 HttpAnswerModel、embedding 与 reranker 入口，也没有能力注册表路由、持久模型路由审计、供应商账单核对和 UNKNOWN 运维对账流程。token 预留是本地准入约束，实际 usage 超过估额会如实形成超额，不能据此承诺供应商账单绝不会超限。预算实时事件页面及更多取消、降级和业务 HTTP 场景仍待验收。[调用边界与连接池修复导读](23-usage-integration.md)
