# 第 23 课：预算、模型路由与有限降级

第 22 课回答“这次改动表现怎样”，本课回答“允许花多少资源、怎样在约束内执行”。超时能限制等待时间，却不能证明供应商没有继续处理请求，也不能替代用量核算。

## 与 Spring Boot 的联系

将预算账本理解为并发库存预留：只先读余额再调用模型，会让多个并发任务同时看到足额余额。应用必须在同一个数据库事务中锁定账户、检查剩余额度、建立调用预留，然后才允许执行。网络等待放在事务外，避免长期占用数据库锁。

账本使用 token 配额，不能把 token 直接称为人民币费用。供应商返回的 usage、应用本地估算和供应商最终账单是三种证据。缺失的 usage 必须标为未知，不能补写为零。

## 一个完整功能单元

1. 建立租户范围内的预算账户和调用预留。预算和模型选项由可信 Java 策略决定，模型或浏览器不能自行提高额度。
2. 调用前原子占额，限制接受的调用次数；同一调用 ID 重放必须幂等，不同估额不能冒用旧预留。
3. 调用发出后按实际 usage 结算一次。实际用量超过预留时如实记录超额，禁止为维持“余额不负”而篡改观测值；后续调用拒绝继续占额。
4. usage 未知时保留在途或未知预留，仅确定没有发出供应商请求时才释放。服务重建后仍能查询账本，不能因内存清空而恢复满额。
5. 将账本接入真实模型执行入口，排队与取消不能产生重复调用；执行事件显示估额、已返回用量、未知用量和拒绝原因。
6. 增加有限模型路由和降级：只允许部署配置中的模型，限制降级次数；权限拒绝、资料不足、取消与预算耗尽不能触发换模型绕过边界。每次新调用都必须重新预留，不能复用上次已消耗的额度。

## 在本项目中定位代码

- `agent/stream/DashScopeAgentStreamer.java` 已解析供应商 usage；日志或返回元数据存在，不等于预算控制已经接入。
- `multiagent/runtime/ExecutionRuntime.java` 管理容量与截止；这些控制可复用，但当前时间预算不能代替 token 账本。
- `security/SecurityDatabase.java` 提供 PostgreSQL 事务基础；租户复合键与并发锁需要专项验证。
- 第 22 课报告中的受控时钟测试用于机制验证，不能拿其物理耗时推导线上成本或吞吐。

## 集中验收

| 检查 | 所需证据 |
| --- | --- |
| 并发占额 | 两个账本实例竞争同一账户，总预留不能超过约束 |
| 幂等与重启 | 同 ID 不重复扣额，参数冲突拒绝，实例重建后记录仍在 |
| 结算与未知 | 实际 usage 重放不重复计费，未知不释放为零，超额如实入账 |
| 租户范围 | 相同账户名称在不同租户独立，跨范围查不到另一方预留 |
| 执行路径 | 真实模型返回 usage 后账本结算；未返回 usage 的失败与取消保留未知证据 |
| 路由与降级 | 正常路由、允许的临时失败、禁止降级的安全失败、达到降级次数分别测试 |
| 页面 | 连续请求、拒绝、刷新与语言切换逐状态截图，保留个人学习状态 |

## 首批工程边界

`usage/TokenBudgetLedger.java` 与 V8 迁移已实现账户锁内的原子预留、幂等绑定、结算、未知和未发送释放。`dispatch` 仅首次转换返回 true；重放者不能再次取得发送许可，但这不保证供应商网络调用恰好一次。发送后丢失回执须保留 UNKNOWN，后续人工对账流程仍待实现。

accepted_calls 是预留受理次数，释放未发送请求不会退还这个计数；它不是供应商实际请求数量。租户来自可信服务构造参数，复合键隔离不等于已完成 HTTP 身份授权。本批不开放公共账本接口，不自动为用户建立满额账户。

`TokenBudgetLedgerPgTest` 的真实 PG 专项验证两实例争抢、重放冲突、超额实记、UNKNOWN 保留、调用次数限制及独立数据库对象重建；没有用对象重建冒充操作系统进程或数据库重启验收。真实模型执行接入、模型路由、有限降级、usage 缺失的运行恢复与预算交互页面仍待完成。
