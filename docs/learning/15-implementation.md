# 第十五课：MCP 工具如何成为真实、受控的执行能力

更新：2026-10-25。任务范围见[六单元任务包](15-mcp-tool-contracts-and-adapters.md)，下一课见[Skill 与业务策略](16-skills-business-policies-and-controlled-tools.md)。这里记录工程实现与证据，不代表个人已掌握或生产环境已验收。

## 先用 Spring Boot 的经验理解

你熟悉的 Controller 定义 HTTP 参数和返回值。MCP 也定义通信契约，但增加了初始化、工具发现、工具输入 schema 和调用结果。模型看到工具定义后提出调用；Java 决定是否允许、怎样执行、何时停止。

| 问题 | 本项目负责的位置 |
| --- | --- |
| 服务提供哪些工具？ | `KnowledgeMcpServer` 注册唯一 `knowledge_lookup_v1`；`KnowledgeMcpClient` 实际初始化与发现 |
| 模型可以调用什么？ | 固定别名 `knowledge__knowledge_lookup_v1`；发现不能扩大本地 allowlist |
| 参数能信吗？ | `McpInputValidator` 严格解析，拒绝重复字段、未知字段、非对象、错误类型和超限 |
| 工具返回 success 就可以相信吗？ | MCP `isError=true` 优先；业务契约、大小和来源仍要检查 |
| 查到的原文还是当前版本吗？ | `McpEvidenceVerifier` 从可信知识接口重新核对 document/revision/generation/chunk/原文范围 |
| 谁负责截止、取消、队列？ | Java 执行层；这些控制对象不来自模型参数 |

`Tool` 是能力，`MCP` 是协议，`Agent` 负责决定下一步，`Skill` 将在第十六课组织受控步骤与业务策略。它们的职责可以分别测试。

## 一条真实调用链

```text
/chat-room 选择 MCP研究助手
  → McpResearchProvider / ResearchRunner
  → 实际 MCP 初始化、发现与 schema 核对
  → 第一次模型请求：选择允许的工具与参数
  → 参数预检，再公开 TOOL_REQUESTED / TOOL_STARTED
  → 实际 MCP SSE → knowledge_lookup_v1
  → 第十三课 RetrievalService → PostgreSQL + pgvector
  → 协议错误/业务结果适配 → TOOL_COMPLETED 或 TOOL_FAILED
  → 可信 HTTP 原文复核
  → 模型队列出队并取得执行许可后，再复核一次
  → 第二次模型请求：基于这次原文整理答案
  → 引用编号与当前资料再次复核 → 最终回答
```

多 Agent 中的 `ResearchAgent` 也复用这条执行器。两次实际模型请求分别经过原有 `ExecutionRuntime` 模型许可和任务调用计数；任务进入终态后不再启动新工具。旧的无工具构造只保留给离线对照测试，不对外声明不存在的工具能力。

MCP 研究类型仅处理本轮研究问题。会话历史与工具事件仍持久化并能恢复展示，但本类型没有把历史答案当成新知识证据，也没有自动读入第十四课的事实偏好；企业知识助手类型继续承担该实验。

## 六个已落地的工程单元

### 1. 版本化只读契约

- `query`：必填、非空、最多 2000 UTF-16 单元。
- `topK`：整数 1–5；`mode`：keyword/vector/hybrid。
- `budgetMs`：教学协议实验允许 100–10000；真实模型不能选择执行预算，客户端按剩余预算覆盖。
- 不接受 tenant/user、SQL、URL、路径、命令或写入参数。教学身份固定 `demo-enterprise`，这不是登录授权。
- 成功空 `hits` 与存储失败是不同结果。返回保留 trace、检索阶段、降级、版本、代数、片段及真实行号/UTF-16 范围。

### 2. 固定版本的真实服务与生命周期

Java 17、Boot 3.4.6、Spring AI Alibaba M6.1 / Spring AI M6 不升级。显式固定 MCP SDK **0.7.0**；实际协商协议为 **2024-11-05**，使用旧版 SSE `/sse` 与 `/mcp/message`，不宣称兼容 Streamable HTTP。

独立服务默认 `127.0.0.1:18135`，知识原文服务为 `18132`，主应用为 `8123/api`。核心应用可以在 MCP 不在线时启动，发现失败明确显示，不把空工具表当成功。

实际验收先后发现并修复：原生 Servlet 异步响应回收竞态；默认 30 秒异步超时；旧传输会话集合不断累积；重复创建客户端时闲置 HTTP 连接耗尽。最终 `SingleClientSseTransport` 复用 SDK JSON-RPC 与 Spring MVC SSE，自行维护一个可信应用连接的所有权、sessionId、跨连接请求映射及清理。新连接替换旧连接，旧结果不广播给新连接；仍保留原 16 个连接上限。

这是单可信本机应用部署，不是多租户 MCP 网关。关闭由拥有资源的应用执行；取消等待不等于远端业务回滚。

### 3. 不可信输入与三种结果视图

`StructuredMcpToolCallback` 保留旧构造并支持稳定服务 ID/别名。限制输入 16384 UTF-8 字节、响应 131072 字节、16 个内容块；拒绝畸形业务壳、受限 schema 外的约束及禁止公开字段。

`ResultViews.original` 是完整的**已适配公开契约**，不是未经处理的秘密协议载荷；`model` 单独受 24576 字节预算约束，超限明确省略 data；`uiPreview` 单独负责展示。研究执行器还检查总输入，给实际模型封装留出余量，不能把字节预算说成真实 token 计费。

除服务器 POST 在解析前限量读取外，SDK 响应和可信原文 HTTP 的大小检查发生在接收后，**不是流式内存防火墙**。

### 4. 原始截止时间、取消与真实资源占用

研究总预算最多 30 秒，覆盖发现、模型排队、网络、原文复核及最终发布。MCP 服务和客户端各 2 个工作线程、8 个等待槽；客户端 SDK 交换串行化。实际后台未退出时，容量不会因为等待超时就假释放。

只读网络 I/O 故障最多重试一次，且保留原始截止、有限退避；参数、权限、协议、业务、取消和超时不据远端 `retryable` 自报自动重试。测试证明写操作的未知结果不被盲目重试；本课未开放实际写工具。

页面“停止接收”先停止浏览器收取，可能短暂等待服务端保存。不能从这个按钮推断远端模型立即停止或不再计费。受控取消信号、迟到结果拒绝和任务终态保护分别由自动测试验证。

### 5. 模型选择与证据检查

真实工具事件来自调用边界；页面不展示私有思维链。公开参数只在预检后记录。远程引用 ID 不是权限证明：发送原文给模型前、模型队列出队后和发布前均核对可信当前原文，覆盖同内容重导的 generation 变化。

已知指令注入隔离复用第十四课局部规则，不能称为完整攻击防护。研究回答检查引用编号与资料有效性，但**没有复制第十四课的逐声明 judge 流程**；本课真实回答的语义支持是人工核对，不能将它说成独立留出集质量门槛已通过。

### 6. 统一页面与工程证据

统一对话新增 Provider 类型，不新建独立聊天页。折叠面板包含真实发现状态、工具 schema、无模型协议实验；执行卡显示实际工具参数、结果及原文入口。当前引用点击时再检查版本与原文，删除或换版后明确拒绝。

### 自动化

`scripts/lesson15/test.ps1`：11 类 **47 项，0 失败、0 错误、0 跳过**。分层如下：

| 层次 | 类/数量 | 覆盖 |
| --- | --- | --- |
| 适配器 | 2 类 / 15 | 严格输入、错误优先、块/字节/字段限制、别名与结果视图 |
| MCP 契约与真实 SSE | 3 类 / 16 | 契约、32 秒闲置、20 次刷新、容量、关闭、取消、旧会话/迟到响应 |
| 实际 PG + MCP | 1 类 / 1 | 当前版本、同内容重导、删除、可信租户隔离、精确原文范围；显式测试 embedding |
| 研究、API与工作流 | 5 类 / 15 | 真实执行路径的替身、公开参数前校验、出队复核、模型预算、任务终态、两次调用计数 |

真实 SSE 测试使用本机 SDK 客户端/服务端；真实 PG 测试必须有数据库，不自动降级。专项本身不调用付费模型。另34类194项相关回归通过，本批共45类241项，均无失败/错误/跳过。前端知识24项、图谱34项共58项通过；生产构建通过，保留既有3D大包提示。图谱109节点、154关系、28课，唯一ID/路径/端点/先修DAG校验通过。

### 真实依赖与模型

- 实际 PostgreSQL 16.15 / pgvector 0.8.6；MCP 使用与资料相同的 `text-embedding-v3` 1024 维 profile。
- 实际停止 PG 进程：MCP `isError=true` 优先，安全诊断为 `MCP_REMOTE_BUSINESS_FAILURE`，没有内存资料。PG 重启后原 `vpn-guide` v2 可查；见截图与 `pg-outage.json` / `pg-restart.json`。
- `qwen-plus` 第一题只召回标题，模型没有编造处理办法；保留该不足。将默认改为混合召回并保留错误码后，同题实际参数为 `query=VPN 401, mode=hybrid, topK=3`，21.5 秒完成，三条结论逐项与 C1 原文核对。
- 这只是开发验收案例，不是新独立留出评测。真实模型与 Embedding 有延迟及失败可能；合成资料首次导入发生过 Embedding 失败，显式重试后成功，未使用替代向量。
- 另一个真实 keyword 请求只召回空结果，执行器在5.7秒后明确无证据，未启动生成；停止接收请求约7秒后保存为 `OUTPUT_INTERRUPTED`，仅记录到工具请求，未启动工具。完整公开事件见截图目录 `real-research.json`。
