# 第24课：把运行身份接入真实容器

这一批使用新的固定提交JAR和独立Compose项目，把上批的数据库版本策略接入实际服务。旧5215管理员迁移基线保留，新5216运行身份组使用不同数据库与卷，不能混用观察。

## 启动顺序与凭据范围

PG就绪后，bootstrap管理员任务创建固定迁移/运行角色和schema，预装vector；migrate使用agent_migrator执行security、knowledge迁移；grant管理员任务授权；三个业务Java服务最后以agent_runtime、AGENT_DB_SCHEMA_MODE=validate启动。运行容器环境没有管理员或迁移密码；迁移服务也不接收模型密钥和内部工具令牌。

管理员仍用于PG初始化和一次性运维任务。这不是取消管理员、采用RLS或为每个业务服务拆分数据库账号。Docker宿主运维者仍能检查容器环境，不能把环境变量注入描述为完整密钥管理系统。

## ACL、角色标志与所有权

REVOKE普通权限不能撤销所有者固有权限，因此脚本分开处理：复制等高权限标志、角色成员关系或运行角色拥有业务对象时直接拒绝；仅CREATE/TEMP的ACL漂移可以显式撤销并再次检查。不会自动接管所有权或替换已有角色密码。

真实测试先给运行角色额外授予CREATE/TEMP，再重跑运维脚本，权限收敛为false。另分别注入REPLICATION和测试表所有权，任务都拒绝；恢复原状态并删除已知空测试表后再继续。所有测试都在隔离容器PG中完成。

bootstrap和grant各自用BEGIN/COMMIT包住整个SQL文件。在全部表DML授权后、撤销Flyway历史权限前故意制造除零错误，实际任务失败且历史DELETE权限仍为false，证明没有留下半笔授权。三项独立运维服务并不是跨进程单个事务。

## 实际验收

新鲜组真实认证、多Agent、MCP空检索与模型拒答成功，两次usage1297+1332=2629；运行与租户周期账本相等、预留归零、工单写入0。重启与重复up后，报告和账本仍可读取，未重复调用模型。

运行身份实际被拒绝建表、改表、临时表、迁移历史写入和SET ROLE agent_migrator。迁移历史installed_by及业务表owner都是agent_migrator。这些是实际容器证据，不能推广为所有业务、任意权限漂移或生产负载均已验证。
