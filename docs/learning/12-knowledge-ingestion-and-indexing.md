**正式教学主线为 PostgreSQL + pgvector；保留 SimpleVectorStore 作为内存对照和离线单元测试方案。** 用户希望获得真实数据库工程经验，本课必须以真实 PostgreSQL 的迁移、数据持久化、更新删除与集成测试验收，内存测试不能替代。本文调整课程任务，不代表已安装数据库或接入 pgvector。

适合能编写 Spring Boot 接口、正在学习 Agent 的开发者。本课沿用“企业知识库与工单助手”业务，以合成的 VPN 故障手册作为资料。每次学习完成一个单元，最后集中验收整个文档生命周期。

## 1. 先理解：让资料成为可以维护的知识

第十一课解决“本次调用怎样装入有限的上下文”。本课解决“候选知识从哪里来、是什么版本、怎样更新和删除”。

例如 VPN 手册把重置步骤从 A 改成 B：应用需要识别资料发生了变化，生成新分块和向量，完整发布新版本，并使旧版本停止参与检索。仅在启动时把文件加载进向量容器，无法说明更新是否完整，也无法解释旧答案来自哪个版本。

几个概念可以映射到熟悉的 Java 后端设计：

| 概念 | 含义 | 后端类比 |
| --- | --- | --- |
| 文档 document | 一个具有稳定身份的资料，例如某租户的 VPN 手册 | 业务聚合的主键 |
| 版本 revision | 文档内容与处理规则的一次不可变快照 | 版本记录 |
| 分块 chunk | 可独立检索、能定位来源的一段文本 | 子记录 |
| Embedding | 将文本转换成供相似度计算使用的数值向量 | 派生计算结果 |
| 索引 generation | 使用同一套模型和处理配置构建的一代索引 | 可切换的数据版本 |
| 索引清单 manifest | 记录文档、版本、分块、状态和当前生效版本 | 业务数据库中的权威记录 |

向量相近不表示事实正确。Embedding 是检索的一个基础，第十三课才比较检索与重排效果，第十四课完成引用与无依据回答策略。

### 本课前后关系

```text
第十一课：选择哪些上下文进入模型
    ↑ 接收带来源的候选片段
第十二课：接入、版本化、切块、索引、更新与删除
    ↓ 提供可过滤、可追踪的候选资料
第十三课：检索与重排
    ↓
第十四课：引用、拒答与记忆
```

第十课 Temporal 是工作流选型实验，**不是第十一、十二课的硬性先修**。本课可以先用同步、可恢复的索引服务理解状态，再根据实际耗时决定是否接入持久化工作流。

## 3. 本课完整功能目标

准备两个演示租户，各自包含同名的 `vpn.md`。验收一条完整生命周期：

1. 首次导入：能看到文档 ID、版本、块数、模型配置和状态。
2. 原内容重复导入：复用结果，不重复调用 Embedding。
3. 只改文件时间：不触发重新嵌入。
4. 修改正文：完整生成新版本，切换后只暴露新版本。
5. 中途失败：旧版本继续可用，失败的新版本可重试或清理。
6. 删除：停止暴露文档，物理索引清理可重试，不能继续返回旧片段。

这里的“暴露”指经过本课查询适配器和清单校验后返回的结果；原始向量容器可能暂时保留未清理的数据，不能绕过适配器直接把结果交给模型。

## 4. 单元一：定义文档、版本与索引清单

### 概念

文档身份和文档内容不同。`documentId` 必须在内容变化时保持稳定；`revisionId` 则在内容或有效处理配置变化时改变。同名文件分属不同租户，不应产生同一文档身份。

### 任务

先写纯 Java 记录及身份规则测试，再实现工厂。以下是待实现契约，可按项目包结构拆成独立文件：

```java
record DocumentKey(String tenantId, String documentId) {}

record IndexProfile(
        String parserVersion,
        String normalizationVersion,
        String splitterVersion,
        String embeddingModel,
        String embeddingRevision,
        int dimensions) {}

record SourceSpan(
        String sourceId,
        int rawStartUtf16,
        int rawEndUtf16,
        int startLine,
        int endLine) {}

record IndexedChunk(
        DocumentKey key,
        String revisionId,
        String chunkId,
        int ordinal,
        String text,
        String contentHash,
        SourceSpan source,
        IndexProfile profile) {}
```

为这些字段定义不变量：

- `documentId` 从可信来源的资料登记 ID 或规范化逻辑路径生成。移动文件是否视为同一资料，要在接入契约中明确；不要默认文件重命名能自动识别为原文档。
- `revisionId` 包含规范化内容 hash 与有效处理配置摘要。时间戳只记录观察时间，不参与内容是否变化的判断。
- `chunkId` 可由 tenant/document/revision/ordinal/块内容摘要确定性生成，包含版本可使新旧版本并存；同一输入重复运行必须产生同一组 ID。
- 该方案不保证在正文头部插入一段后，所有后续分块 ID 都保持不变。若追求局部重用，需要另做内容边界与重复片段消歧方案。
- 使用长度前缀或规范化编码生成摘要输入，不使用存在分隔符歧义的简单字符串拼接。
- 清单至少记录原始文件摘要、规范化内容摘要、配置摘要、状态、生效版本、分块 ID、错误码、更新时间。状态考虑 `BUILDING/READY/ACTIVE/FAILED/RETIRED/DELETED`，明确哪些是版本状态、哪些是文档状态。

**交付与验收：** 同租户同源重复运行 ID 一致；不同租户同名资料不混淆；修改正文或切块配置产生新版本；只改 mtime 不重新计算向量。文档、版本和 generation 的唯一约束要写清楚。

## 5. 单元二：安全读取、规范化与来源定位

### 概念

解析会改变文本。Markdown 标题符号、换行或代码块被移除后，分块字符串的位置通常不再等于原文件位置。引用必须说明坐标系，否则“第 100 个字符”无法复查。

### 任务

1. 首批只接入 UTF-8 Markdown 和纯文本，拒绝其他格式；PDF、OCR、压缩包留作独立扩展。不要通过改后缀假装已支持。
2. 配置并在读取前后检查文件字节数、解码后长度、文档数、单批总大小；严格处理非法 UTF-8、空文本和异常长行。设定可取消的处理期限。
3. 只读取登记的本地根目录内文件；解析实际路径后校验越界与符号链接，拒绝用户输入任意服务器路径或远程 URL。文件名不是权限凭据。
4. 保留原始资料的不可变快照。规范化版本可统一换行、处理 BOM；不要悄悄删除所有空白或改写代码语义。
5. 保存规范化文本到原始文本的映射，或采用保留原始区段的解析器。代码块是否保留、块引用是否保留应成为显式策略；当前 Reader 配置忽略两者，不一定适用于故障手册。
6. 来源坐标采用 Java UTF-16 的半开区间 `[start,end)`，只在合法 code point 边界切分，行号从 1 开始；另外记录位置所属的原文版本。中文、emoji、CRLF、重复句子必须有测试。不能用 `indexOf(chunkText)` 猜测重复段落的位置。

若当前 Reader 无法提供可靠原文映射，应明确先实现可定位的纯文本/保留原文 Markdown 路径，再扩展复杂解析，不把规范化后 offset 标成原文 offset。

**交付与验收：** 给定块可定位并核对原文内容；失败返回结构化错误，导入结果包含失败文档，不能吞异常后报整批成功。

## 6. 单元三：切块与可重复的向量计算

### 概念

块太大可能混合多个主题，太小可能丢失前提。重叠窗口可以保留边界上下文，也会增加索引数量和重复召回。字符数、token 数、字节数是三种量，不能混用。

### 任务

1. 用实际 VPN 手册比较“按段落/标题保留语义”和“token 上限切块”。显式记录上限、重叠、空白处理、tokenizer/切块版本，不把构造器位置参数猜成某种含义。
2. 为每块保存标题路径、顺序、内容摘要与来源；分块有重叠时来源区间也允许重叠。
3. 定义自己的 Embedding 适配端口，让纯测试可记录输入、返回固定维度向量、注入第 N 块失败；接入 M6 时再调用实际 `EmbeddingModel`。
4. 模型身份应包含供应商、模型名称、可获得的版本/部署标识及维度。模型名相同但后端版本变化时仍需明确索引兼容策略，不能只比较维度。
5. 缓存键包含规范化块文本摘要、影响向量的处理配置、Embedding 模型版本。不要把导入时间或文件 mtime 加进键；隔离租户缓存，避免跨租户命中透露资料存在性。
6. 仅把稳定正文传入向量计算。若适配器把 metadata 格式化后一起嵌入，要明确选择字段；易变时间或生成关键词不能意外改变实际向量输入却未改变摘要。

M6 接入时的元数据转换示例：

```java
// 设计示例：字段已由服务端校验，元数据值采用明确可序列化类型。
Map<String, Object> metadata = Map.of(
        "tenantId", chunk.key().tenantId(),
        "documentId", chunk.key().documentId(),
        "revisionId", chunk.revisionId(),
        "ordinal", chunk.ordinal(),
        "sourceId", chunk.source().sourceId());
Document document = new Document(chunk.chunkId(), chunk.text(), metadata);
vectorStore.add(List.of(document));
```

`VectorStore.add` 通常负责调用所配置的 EmbeddingModel；不要既手动 `embed` 又调用会重新嵌入的 `add`，造成重复计费。测试替身与真实接入分别统计调用次数。已算好的向量是否能直接写入，需要查具体后端接口，通用 `VectorStore` 不承诺该能力。

**交付与验收：** 固定输入分块确定；来源可复查；重复导入模型调用数为零；维度不符拒绝发布。关键词补全是可选增强，不应成为理解基础导入所必需的付费调用。

## 7. 单元四：增量发布、失败恢复与模型迁移

### 概念

本课主方案将清单、分块与向量放在同一个 PostgreSQL 数据库，**通过同一连接和事务管理器执行的 SQL 可以一起提交或回滚**。但远程 Embedding 请求不属于数据库事务，不能在持有长事务或行锁时等待模型。若以后接入独立外部向量库，还会增加跨存储一致性问题。

因此仍然先构建新版本、验证完整性、切换生效版本，再清理旧数据。推荐将解析/Embedding 与短批次写入分开；新版本的批次落库保持 `BUILDING`，最后在短事务内校验完成清单并条件切换 `ACTIVE`。失败时旧版继续可读，恢复任务处理未完成版本。

### 任务

实现如下状态推进，并先写故障测试：

```text
读取清单 → 相同内容和配置？→ 是：返回 UNCHANGED
               ↓ 否
登记 BUILDING → 新版本分块/嵌入/写入 → 验证预期块数与完成清单
               ↓ 失败                 ↓ 全部完成
             FAILED                 READY
       旧 ACTIVE 保持可读              ↓ 原子比较并切换
                                    ACTIVE
                                      ↓
                               旧版本 RETIRED → 可重试清理
```

- 新旧块 ID 不覆盖彼此；部分写入留在非 ACTIVE 版本，重试相同版本应幂等。
- 不假定 `PgVectorStore.add()` 会和清单操作自动共享事务，更不能认为它让远程 Embedding 与所有 SQL 原子提交。实施时检查 M6 具体实现及事务传播，用真实 PG 失败注入验证实际边界；必要时通过自己的存储适配分离“计算向量”和“事务写入”。
- 生效切换对清单做版本条件更新，防止两个并发更新中较旧版本最后完成却覆盖新发布；删除后的旧任务也不能重新激活文档。
- 查询适配器必须排除非生效版本和已删除资料；每次查询使用一致的生效版本视图，必要时发布前后校验清单版本，避免切换瞬间混读。物理清理旧版本需要考虑在途读者。
- 仅在 TopK 结果出来后过滤旧块可能造成结果不足；这可避免返回旧数据，但不能保证召回率。检索侧需要可下推过滤、隔离 generation 或有界补取策略，第十三课继续比较。
- 在新版本写完、清单切换之前崩溃：恢复时核对分块清单与配置，继续构建或清理；在切换后、删旧之前崩溃：新版本继续可读，恢复清理旧块。
- 增量判断以内容与配置摘要为准。原始文件字节变化但规范化内容未变，可更新观察记录而复用向量；仍需说明该次原文快照与 offset 如何对应，不能沿用错误坐标。
- Embedding 模型、维度或关键处理配置改变时建立新 generation。构建完整新索引后切换，查询使用相同模型配置。即使维度相同，也不能把不同语义空间的向量直接混合排名。

主线必须持久化清单和向量，并实际重启应用及数据库验证恢复。内存对照可以展示重启后数据丢失的差异；即使为 SimpleVectorStore 另加快照，也不能把其快照恢复当作 PostgreSQL 的恢复证据。本课不以“先全在内存实现”替代数据库交付。

**交付与验收：** 在第 N 块失败、发布前失败、发布后清理失败三个位置注入异常；记录生效版本、可见块与补偿结果，证明没有半成品发布。

## 8. 单元五：删除、租户边界与运维入口

### 概念

删除是一条业务操作。应先使资料在授权查询路径中不可见，再物理清理派生数据；清理失败需要继续处理，不能无期限静默遗留。

### 任务

1. 建立独立实验导入入口或服务方法，返回 `jobId/documentId/revisionId/status/chunkCount/errorCode`。失败信息脱敏，不回显密钥、服务器绝对路径或原文全文。
2. 删除时先原子记录删除状态、取消待发布版本，再按清单删除所有相关块。重复删除幂等；物理清理失败记录待处理状态并提供重试。
3. 两个同名资料的演示租户分别导入、查询和删除，证明删除 A 不影响 B。所有 repository/vector adapter 方法都显式带 tenant 范围。
4. 本课 tenant 由受控演示配置注入。metadata 的 `tenantId` 和请求里的 tenant 参数**不是可信授权**，不开放成生产多租户接口；第十七课接入认证身份并检查所有访问路径。
5. 文档中的“忽略权限”等文本始终作为资料，不能改变服务端导入根目录、索引范围或工具权限。进一步注入与隔离在第十八课展开。
6. 输出可阅读的索引报告：新增/不变/更新/删除/失败数量、模型调用次数、配置版本、清理积压。用户应能从业务状态看懂发生了什么，不需要逐行断点。

**交付与验收：** 删除后通过查询适配器不能获得旧块；旧构建任务迟到不能复活资料；能区分“逻辑删除已生效”和“物理清理已完成”。第十四课再定义已生成引用、快照及历史回答的留存与撤销策略。

## 9. 单元六：集中验收与独立变式

### 先自动测试，再单独记录外部验证

下面是**待执行矩阵**，本文未宣称任何一项已通过。实现时先写预期和能失败的测试，再补逻辑，最终运行本课测试及第十一课相关回归。

| 类别 | 输入/故障 | 必须断言 |
| --- | --- | --- |
| 身份 | 同租户同源、跨租户同名、重复段落 | ID 可重复、跨租户区分、块序号消歧 |
| 增量 | 原文不变、只改 mtime、正文改变 | 前两者不调用 Embedding；变化产生新版本 |
| 解析 | 空文、非法编码、超限、越界路径 | 明确拒绝，不触发向量计算 |
| 来源 | 中文、emoji、CRLF、重复段落、重叠块 | 原文 offset 可核对，不切开 surrogate pair |
| 配置 | 切块策略、模型版本、维度变化 | 新 generation；配置不匹配不能发布 |
| 中途失败 | 第 N 次 Embedding 或写入失败 | 新版本不可见，旧版继续可用，重试不重复记录 |
| 发布竞争 | 两个版本并发、删除与发布竞争 | 条件切换正确；旧任务不能覆盖或复活 |
| 删除 | 重复删除、部分物理删除失败 | 立即逻辑不可见，清理可重试，不删其他租户 |
| 进程恢复 | 构建中、切换前后分别重启 | 若声明持久恢复，必须真实子进程与同一持久资料验证 |
| 查询对接 | 新旧版本混存、TopK 被旧块占据 | 不返回旧块；记录结果不足与检索策略边界 |
| PG 迁移与约束 | 空测试库、重复启动、重复块 ID、错误维度 | 迁移版本正确，唯一约束生效，错误向量拒绝写入/发布 |
| PG 事务 | 分块写入后故障、发布事务中途故障 | 事务内 SQL 回滚，已完成的构建批次仍非 ACTIVE；旧版可读 |
| PG 并发 | 独立 JDBC 连接并发导入、发布与删除 | 验证真实行锁/条件更新和唯一约束；不能只用 synchronized 模拟 |
| PG 持久化 | 应用与数据库分别重启 | 同一持久资料的清单、块、向量及生效版本可读取 |
| PG 检索基线 | 固定向量与问题集、精确查询与近似索引对照 | 结果与过滤正确，记录查询计划和近似召回边界，不假设小样本必走索引 |

故障对照练习：

| 故障 | 容易出现的问题 | 本课预期行为 |
| --- | --- | --- |
| 启动时每次全量 add | 重复向量调用，缺少变更证据 | 按内容和配置摘要复用 |
| 更新时先删旧版本 | 中途失败后无可用资料 | 新版完成后切换 |
| 仅按文件名删除 | 误删别租户同名资料 | tenant + document + version 范围定位 |
| 只改模型名配置 | 查询与索引语义空间不一致 | generation 隔离和明确迁移 |
| 失败被 loader 吞掉 | 半批成功被报告成全部成功 | 单文档结果与批次状态可核查 |

验收分三层记录：① 离线单元测试使用合成资料、可控向量替身和内存对照；② 真实 PostgreSQL + pgvector 集成测试使用可控 Embedding，验证 SQL、迁移、检索、事务、并发与持久化；③ 真实 Embedding 接入及质量验证单列供应商、模型、配置、资料集版本、调用数量、费用与结果。第二层不能被第一层替代，第二层通过也不代表第三层模型效果已验证。基础测试不依赖凭据、外部网络或整个 Spring Boot 初始化；数据库测试应明确外部运行依赖与执行结果，不能静默跳过后报告整课完成。

### 独立练习

将一份 VPN 手册分成“账号问题”和“网络问题”两份资料，设计原资料撤销与新资料发布顺序，说明是否允许短暂共存、如何追踪历史来源。先写测试与状态表，再实现；不要只修改分块大小。

## 10. 面试复盘

每题按“问题 → 方案 → 取舍 → 证据 → 边界”回答：

1. **为什么不用文件名当文档 ID？** 说明同名、租户、重命名与内容变化；给出稳定主键和版本主键的区分。
2. **如何增量更新知识库？** 描述规范化内容与配置 hash、块清单、新版本构建、条件发布及旧数据清理；解释本课同库短事务如何保护发布、远程 Embedding 为什么不能由本地事务回滚，以及独立外部向量库增加的一致性问题。
3. **删除了文件为什么还可能被检索？** 区分资料目录、清单、向量索引、缓存和在途请求；说明逻辑删除与物理清理的两阶段路径。
4. **怎样选择分块大小？** 从标题、段落、上下文完整性和 token 限制出发；用固定问题集比较，不能只背一个固定数字。本课验证机制，第十三课评估召回。
5. **换 Embedding 模型为什么要重建？** 维度相同也不代表语义空间兼容；说明 generation 构建、查询模型绑定、切换与回退。
6. **metadata 里加 tenantId 是否就安全？** 还需要可信身份、访问范围校验、检索前过滤及工具侧授权；本课只做受控演示，第十七课补齐认证链路。
7. **为什么选择 PostgreSQL + pgvector，而不是一直用内存？** 结合真实迁移、事务、约束、重启与运维证据解释选择；比较精确检索与近似索引、过滤与召回的取舍，并明确本课没有完成生产容量和高可用验收。
