# 第十九课：人工审批与受控工单写入

本课从第十六课的待审批草稿出发。模型可以生成建议。服务端保存一份不可变的提案，由同租户的另一位有权限的人审阅，再执行经过批准的写入。

## 已实现的审批规则

`TicketApproval` 绑定提案 ID、提出者、工单操作 ID、参数摘要、版本与截止时间。审核人必须和提出者属于同一租户，且是不同主体。审批结果会创建新版本。拒绝、过期、版本过旧、操作 ID 或参数摘要不匹配时，无法取得写入命令。执行时要求原审批会话，当前权限仍需由正式执行入口检查。

先阅读 `TicketCommand.fingerprint()`，再运行以下回归。尝试只改标题或只改操作 ID，观察两种变更都使审批失效。

```powershell
mvn.cmd '-Dtest=TicketApprovalTest,TicketReliabilityTest,TicketApiTest' test
```

## PostgreSQL 中的审批和写入

`TicketApprovalWorkflow` 把服务端授权和业务写入放入同一个 PostgreSQL 事务。普通员工可提出工单，专职 `ticket-approver` 可审核和执行。审核仍需满足同租户及双人约束。仓储按租户与提案 ID 锁定数据，审批决定按预期版本保存。写入以租户和操作 ID 去重，重复执行返回已提交的同一工单。

权限决定先写审计，业务写入放在保存点之后。业务失败只回滚业务部分，拒绝决定仍可提交审计。已有回执仍需当前审批会话和授权才可读取。HTTP、从已保存草稿提取提案以及审批页面仍待接通。

本批用隔离 PostgreSQL 16.15 实测从 V2 升级到 V4。28 项联合回归通过。数据库用例覆盖角色分离、跨租户查询、事务回滚、并发执行只产生一条工单、重试返回原回执，以及审批会话撤销后的执行拒绝和审计。测试通过应用服务直接调用审批和写入，本批没有模型调用。[图谱入口验收](../images/lesson19-approval-2026-11-13/README.md)

## 工程任务

1. 提案从当前主体可访问且已持久化的 Skill 草稿创建。服务端生成操作 ID 和摘要，保存草稿来源、主体、租户、审批版本和截止。提案创建后修改参数需要发起新提案。
2. 增加审核入口，从可信会话识别当前主体与租户。检查审批权限、资源归属和双人约束。使用 PostgreSQL 行锁或版本比较，使并发审批只能提交一个决定。记录提出、通过、拒绝与过期的审计。
3. 在正式写入入口重新检查会话及权限，读取已批准的原始命令。用同一事务保存工单与幂等回执，操作 ID 唯一性按租户约束。响应丢失后的同参数重试返回已有回执，参数冲突返回错误。
4. 在统一页面展示待审批、拒绝、过期、已批准、已写入和权限失效。只有提交后的工单回执可以显示写入成功。模型输出与草稿的成功状态保持独立。

## 验收

- 用真实 PostgreSQL 验证自审、跨租户、过期、撤权和拒绝，确认工单行数无变化。
- 两个并发审批请求只提交一个决定。批准后的并发重试只产生一条工单和一个回执。模拟事务回滚及提交后响应丢失，再核对持久化结果。
- 用两组测试账号操作页面，逐状态截图。记录真实模型产生的草稿和人工批准产生的数据库回执，并保留个人学习记录。
- 图谱同步实现状态与验收证据。练习时解释参数摘要、当前授权和数据库唯一约束各自处理哪一类失败。
