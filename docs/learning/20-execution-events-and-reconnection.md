# 第二十课：执行事件、SSE 与断线恢复

**工程任务**：让已提交的多 Agent 任务在关闭页面后继续执行。重新打开页面时，用户能从上次收到的事件继续查看，并在服务重启后查询已有运行与结果。

## 先看现有实现

第 5、7 课提供了事件序号、运行查询和取消。正式多 Agent 页面使用 `FormalMultiAgentController` 查询和取消运行，`runRevision.ts` 丢弃切换运行或身份后迟到的请求。当前 `RunRegistry` 是单进程登记表，进程重启会丢失其中的运行状态。本课的持久化针对正式多 Agent 运行。聊天页面已有的文件历史仍按其原有约定恢复。

## 概念与代码落点

| 概念 | 实现任务 |
| --- | --- |
| 快照 | 在 PostgreSQL 保存租户、运行 ID、当前状态、最后事件序号及终态结果。先设计最小可展示的公开字段。 |
| 事件日志 | 每个运行的公开事件序号严格递增。通过唯一约束拒绝重复落盘。快照与事件在同一事务提交，避免快照指向未保存事件。 |
| SSE 游标 | 服务端为事件设置 `id`，重连时读取 `Last-Event-ID` 或经过验证的显式游标。先补发游标之后的已提交事件，再订阅后续更新。补发与订阅之间应能发现遗漏。 |
| 重连与取消 | 停止接收只关闭订阅，取消走现有正式业务入口。进程重启后，无法恢复执行的非终态运行应标为中断，保留已提交事件和执行证据。 |
| 权限 | 查询快照、补发、订阅和实际发布分别校验当前会话与运行归属。日志保存经过公开投影的内容。 |

## 实作与验收

1. 用 PostgreSQL 测试覆盖重复写入、快照和事件的事务一致性、跨租户隔离及重启后查询。
2. 用序号断言重连时无缺口。客户端收到同序号事件应幂等处理，检测到缺口时重新同步。使用游标超出范围、保留期已过和会话撤销测试失败分支。
3. 在正式多 Agent 页面启动有多个可见阶段的运行，记录最后收到的事件 ID，关闭连接后重新进入。逐状态截图检查重连、补发、完成和单独取消。
4. 在真实模型链路核对最终报告与持久化快照。用一次受控重启验证查询仍然可用，并记录中断运行与已完成运行的不同处理。

面试练习：浏览器已接收事件 12，服务端已提交到 15。解释断线时 13–15 如何恢复，怎样处理重复的 12，以及为何关闭 SSE 连接不能作为取消确认。
