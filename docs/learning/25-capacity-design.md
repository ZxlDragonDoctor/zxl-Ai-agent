# 第25课实施设计：有界负载与背压证据

本批复用正式多Agent的协调池、工作池、模型信号量与持久化报告；不添加第二套执行引擎。授权来自项目协作约定的逐批实现全部课程；按该授权直接实现和验收。

备选方案：仅测线程池便于定位但不能代表HTTP和PG；直接大量真实模型压测会混入供应商限额和费用；本批选择小规模、有硬上限的正式HTTP探针，再以确定性Runtime回归定位本地容量，单列真实模型证据。此选择不把局部测试当成端到端容量。

探针位于scripts/lesson25，输入明确的本机127.0.0.1 origin、已有登录cookie/CSRF、目标和负载参数。并发与请求总数均有限，单次HTTP和整个运行等待均有时限，禁止重定向，不自动重试POST。每个虚拟用户保持运行到终态再提交下一项；这是闭环负载，不估算开放到达率下的吞吐。

输出不包含cookie、CSRF、目标、回答或原始异常。分别统计HTTP拒绝、202后异步容量失败、排队超时、完成、取消、其他失败和观察超时。提交与观察终态延迟分开，分位数使用最近秩法，给出样本数；超时不能当成快速完成。观察到cleanupPending须保留，不能把业务终态当成资源释放。

测试先失败再实现：使用本机真实HTTP夹具验证并发上限、429、202后容量失败、超时与取消、不跟随重定向、输出脱敏及分位数。真实应用验收另行记录固定版本/配置、负载和全部结果，不预设成功SLA。运行中发现Runtime缺陷先补确定性回归再修复。

后续按职责提交探针、运行控制修复、课程图谱与截图。个人学习状态不变。第25课完整验收仍需要受控与真实模型场景、恢复后新运行及页面反馈；单次小负载结果不构成生产容量或供应商承诺。
