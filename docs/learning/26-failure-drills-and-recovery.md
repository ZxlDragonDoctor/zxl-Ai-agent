# 第26课：故障演练与恢复验证

故障演练从不变量开始：每次运行只有一个业务终态；取消后不再启动新动作；审批的业务写入按幂等键最多一次；未知模型用量不随重启退款；恢复后旧数据仍可读。页面红灯只能证明出现错误，不能证明这些不变量成立。

本课是下一批完整工程任务，尚未完成综合实现和验收。已有第17—24课的权限、数据库、MCP、事件与预算证据可以复用，但不得把分散的历史成功相加为一次综合演练通过。

## 一个完整功能单元

建设可重复的隔离演练运行记录：每项记录固定版本、注入前基线、注入点、请求UUID、预期、实际终态、PG独立读数、清理状态、恢复动作和恢复后新请求。凭据、对话全文、备份与展开后的环境文件不进入记录。

| 故障 | 注入方式与预期 | 验收证据 |
| --- | --- | --- |
| 模型等待中断/超时 | 在确定性HTTP模型夹具挂起响应；总截止阻止下游启动，实际连接停止单独核实 | 失败优先测试、调用次数、终态及cleanupPending轨迹 |
| PG暂时不可达 | 只停止隔离演练数据库，权限/发布失败关闭；恢复后原会话和新请求可用 | 真实PG、原数据哈希、失败与恢复截图，不切内存 |
| MCP/Worker中断 | 只停止演练Worker；工具失败不伪装空召回或引用成功 | 真实HTTP错误分类、事件、重启后新请求 |
| 双人重复审批 | 同一待批草稿并发批准；幂等回执一致、业务写入一条 | PG事务/并发测试、双身份页面及独立SQL |
| SSE断线 | 记录cursor后断线并重连，禁止重复应用旧序列 | 真实事件序列、重启后恢复、页面持续操作 |
| 预算耗尽及重启 | 并发预留触及限额，拒绝新模型调用；UNKNOWN不退款 | 真实账本、模型夹具次数、重启前后余额 |
| 撤权与恢复 | 工具执行期间撤权，停止发布敏感结果；恢复权限后新运行按新授权执行 | 两租户隔离、PG审计、无结果泄漏与失败终态 |

## 实施顺序

1. 核对已有用例与服务启动方式，固定隔离项目名/端口/数据卷，检查目标是本次演练创建的资源；不得停止用户其他运行组。
2. 先补能复现未覆盖竞态的确定性测试；使用latch/受控时钟和真实HTTP夹具，保留现有截止、权限、幂等断言。
3. 建立带显式上限和固定错误分类的演练脚本。注入与恢复分开记录；失败后保留现场，不自动删除数据或以重建空库冒充恢复。
4. 用真实PG/MCP复跑数据库、Worker、审批、事件场景，再单列少量真实模型请求，不用夹具通过替代真实供应商证据。
5. 前端逐状态操作：正常基线→故障→错误说明→恢复→读回旧结果→新请求成功；中英文与图谱入口同时复核，截图附预期和实际。
6. 同步图谱的源码/文档关联和实施边界，细分提交并推送。课程实现进度不能修改个人掌握状态。
