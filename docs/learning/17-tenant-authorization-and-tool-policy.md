# 第十七课：可信身份、租户隔离与工具授权

状态：**完整六单元学习任务包；第十七课工程尚未实现、尚未验收**。编写日期：2026-10-25。本文描述下一批必须落地的功能与证据，不能作为功能已经完成的证明。个人掌握状态保持不变。

先修：[第十六课 Skill 与受控工具范围](16-skills-business-policies-and-controlled-tools.md)、[第十五课 MCP 实现](15-implementation.md)、[第十二课真实 PG 知识接入](12-implementation.md)、[第十四课引用与确认记忆](14-implementation.md)。第十六课实施中的类名，以该课交付时的源码和实现记录为准。

业务目标：甲、乙两个企业使用同一套知识与工单分析助手。甲企业员工只能使用自己的知识、会话、记忆与任务；模型不能通过填写身份字段或伪造工具名称获得乙企业数据。管理员撤销权限后，排队任务和迟到结果也必须受约束。

## 1. 先从 Spring Boot 接口理解三个概念

| 概念 | 回答的问题 | 本项目中的例子 |
| --- | --- | --- |
| 认证 Authentication | 当前请求究竟是谁发出的？ | 服务端验证会话凭据，建立主体和有效租户成员关系 |
| 授权 Authorization | 这个主体现在能对这个资源做什么？ | 当前用户可以读甲企业手册，但不能删除手册或读取他人的私有会话 |
| 审计 Audit | 实际检查、执行或拒绝了什么？ | 某次运行在出队时发现权限已撤销，因此没有调用 MCP |

你熟悉的 Controller 参数来自用户输入。`tenantId` 即使类型正确、通过了 JSON 校验，也不能因此成为可信身份。模型生成的工具参数、检索资料、Skill 文本同样不能建立主体。身份必须从服务端验证过的认证上下文取得。

把授权理解为一个有输入、有返回值的 Java 策略判断：

```text
允许 = 有效认证会话
     ∧ 当前有效的租户成员关系
     ∧ 主体对资源和动作有权限
     ∧ 服务端政策、Agent、Skill 的工具范围均允许
     ∧ 资源当前版本与执行状态仍有效
```

“没有找到知识”和“没有权限查询知识”是不同结果。对不可见资源，公开响应可以统一表现为资源不可用，避免泄露其存在；内部审计仍记录真实拒绝原因。

## 3. 单元一：建立可撤销的可信认证主体

### 概念

认证成功后建立的主体应不可变，但它不是永久通行证。运行可以保存“谁创建了它”的快照；之后是否仍可执行，要向当前权威会话和权限状态查询。不能在创建时复制一次角色，便永远允许后续动作。

### 实践任务

1. 为本地课程实现真实的服务端认证边界。建议采用服务端保存的随机不透明会话凭据，凭据只存摘要，包含过期、撤销状态和会话版本；设置有界会话数量。通过现有受维护的安全组件处理密码，禁止自创密码散列。演示账号由受控环境初始化，不提交密码、会话令牌或个人配置。
2. 建立主体模型，例如 `AuthenticatedActor(subjectId, tenantId, sessionId, authenticationVersion)`；租户是已验证成员关系的选择结果，用户提交的候选租户必须经过服务端成员检查。匿名、失效、过期、撤销、伪造的会话一律不能产生此对象。
3. 本课采用同源网页会话时，明确 Cookie 的 HttpOnly、SameSite、有效路径与生产 HTTPS 的 Secure 配置；写请求实施 CSRF 防护。开发 HTTP 与生产 HTTPS 的差异要写入配置说明，不能以“本机使用”为由跳过认证。
4. 身份只通过受控请求上下文传播。异步任务显式携带不可变身份引用，执行时重新解析有效权限；不能依赖线程池工作线程上一次残留的 ThreadLocal。请求结束、异常和取消均清理上下文。
5. 实现登录、当前主体、退出和会话撤销的最小闭环。区分未认证的 401 与已认证但动作不允许的 403；针对跨租户资源采用一致的公开不存在/不可访问策略，不返回对方主体、标题或租户明细。

**交付与验收：** 认证契约、必要 PG 迁移、凭据生命周期与主体传播测试。伪造 Header/JSON 的 `tenantId`、`userId`、角色不改变主体；重用已撤销会话失败；同一线程先处理甲再处理乙不会继承甲身份。此为课程内认证实现，未接企业 SSO、MFA 或外部身份提供商时应明确记录。

## 4. 单元二：在真实 PG 中隔离所有资源读取与写入

### 概念

租户隔离必须在数据库取数之前约束范围。先全库向量检索、返回若干条，再在 Java 中删掉不允许的记录，会使不可见内容进入召回过程，还可能因占满候选导致有权限的资料漏查。

### 实践任务

1. 在同一真实 PG 中建立 `tenant-alpha`、`tenant-beta` 的合成测试数据；两边故意使用相同 `documentId`、相同问题和不同秘密标记，检查复合标识和查询条件。使用至少“知识只读员工”和“知识维护者”两种角色，并补同租户不同用户的私有会话/记忆案例。
2. 明确资源所有权：知识按租户与可见范围；会话、个人确认记忆按租户加所有者；运行、步骤、事件、草稿按所属业务资源继承。管理员是否能查看个人会话必须显式设计，不能由角色名称自动推定。
3. 对知识清单、原文详情、导入、删除、关键词检索、精确/近似向量检索、混合召回、重排输入逐项强制范围。SQL join、更新和删除均含可信租户条件；外键与唯一键考虑租户，防止 ID 碰撞串联。
4. 将旧文件会话补上可靠的所有权规则。未知历史归属的数据不向新登录用户默认公开；提供受控迁移或隔离区，保留用户原始历史与备份。不能清空旧会话来通过隔离测试。
5. 对缓存、去重与后台导入使用完整范围：租户、必要的主体/资源可见性、版本/权限代际、模型 profile 等。若当前无此类缓存，记录“未部署”，不要为课程临时引入；通过代码盘点证明不存在遗漏的跨租户复用路径。
6. SQL 参数化和租户条件是本课主线；数据库 RLS 可以作为额外防线对照，但不能只启用一个策略便声称全覆盖。若采用 RLS，另测连接池复用、事务上下文、应用角色权限以及所有者/特权角色绕过边界。

**交付与验收：** 数据模型与迁移说明、真实 PG 双租户正反向查询/更新/删除/并发测试。包括原文、引用回源、记忆、会话、运行和事件，而非只验证 search。PG 不可用时明确失败，不回退 SimpleVectorStore。迁移、并发、重启后身份与数据持久性分别取证。

## 5. 单元三：让 MCP 与 Skill 的每次实际调用都授权

### 概念

服务发现知道“有什么工具”，认证知道“调用者是谁”，授权决定“这次能不能调用”。MCP 连接 ID 只表明连接归属，不能替代租户身份；Skill 工具清单也不能扩大调用者权限。

### 实践任务

1. 建立统一动作与资源模型，例如 `knowledge.read`、`knowledge.manage`、`conversation.readOwn`、`skill.execute`。为每个实际工具建立受审查映射：服务 ID、原名/暴露名、契约版本、只读/写入属性、所需动作。未知工具默认拒绝。
2. 在提供模型工具列表时收缩范围，并在真正 dispatch 时重新计算“服务端政策 ∩ 当前主体权限 ∩ Agent 范围 ∩ Skill 范围”。直接调用调度服务、伪造别名、修改参数或绕过前端不能绕过第二道检查。
3. 明确应用到本机 MCP 服务的信任协议。推荐把模型业务参数和可信调用上下文分成两个通道；服务端验证短时授权凭据/受控服务上下文、受众、目标动作和有效期，再按绑定租户查询。不能把任意客户端传来的 tenant Header 当可信，也不能复用一个全租户管理员服务凭据后直接相信模型参数。
4. 固定 MCP transport 的连接所有权与业务主体分开管理。共享连接内的每次请求都绑定实际调用者；并发甲乙请求、迟到响应、重新连接不能串主体。若实现选择每租户独立客户端，也必须给客户端池设容量、归属、过期和关闭规则，并验证撤销不会因缓存连接失效。
5. 原文验证器、检索诊断 API、来源窗口、模型上下文装配和历史回看走同一授权边界。不能 MCP 查到甲知识，再让一个无认证固定 demo 接口返回乙原文。
6. 保留第十六课版本快照与工具摘要；Skill 默认版本更新不修改旧运行快照，当前权限撤销仍立即约束后续调用。本课不开放终端、任意 URL/SQL/文件路径或真实工单写入；写入审批在第十九课建设。

**交付与验收：** Java 策略和 MCP 服务端的契约/集成测试，未知/越权工具零实际调用；甲乙并发相同查询只获得各自资料；远端伪造、过期授权和错误受众被拒绝，拒绝结果不带敏感参数、令牌或对方内容。若只完成应用侧检查、MCP 仍是固定 demo 身份，必须标为本单元未完成。

## 6. 单元四：处理撤销、排队与发布时序

### 概念

检查权限与使用结果之间有时间差。任务入队时允许，不代表出队时还允许；工具已经返回，也不代表现在可以把资料发送给模型或用户。

```text
入口认证/授权 → 建立运行快照 → 等待执行
  → 出队重新授权 → 工具实际调用前重新授权
  → 资料进入模型上下文前重新授权
  → 最终结果/公开事件持久化与发布前重新授权
```

定义本课可验证的撤销语义：**撤销事务提交后，后续开始的受保护动作必须拒绝**。先前已经发出的字节不能收回；已发往模型供应商的资料也无法通过本地取消撤回。必须用受控时序测试说明检查与发布的同步边界，避免承诺没有实现的全局瞬时撤销。

### 实践任务

1. 在权威存储中维护会话/成员/权限版本，撤销在事务中提交。检查缓存若存在，必须明确一致性机制；本课主验收不能用任意 TTL 窗口隐瞒已撤销权限。
2. 运行保存创建者、租户、会话引用与当时版本用于追踪；重新检查时不能只比较本地复制值。服务不可用、权限状态无法确认时，受保护动作失败关闭，不能继续沿用旧权限。
3. 用闩锁或受控网关建立确定性场景：任务排队后撤销、工具返回后撤销、模型队列等待时撤销、生成完成但发布前撤销。分别断言未调用下一个组件、未发送越权模型上下文、未公开答案与工具证据；保留可理解的公开拒绝终态。
4. 已经进入外部调用的任务请求本地取消，迟到返回只能丢弃，不能覆盖终态或进入新会话。内部审计可记录被阻止的动作和原因，不保存越权原文作为面向用户的错误详情。
5. 重新打开旧引用、读取历史消息、恢复事件流仍按当前权限检查。若历史回答包含已撤销资料，说明访问策略并在服务端执行；仅隐藏来源按钮而继续返回正文不能算保护。
6. 区分“只读调用被阻止”和“写动作已回滚”。本课不引入可自动写入的业务能力；第十九课将审批、操作 ID 与执行前再授权绑定。

**交付与验收：** 撤销时序图、事务边界说明、确定性并发测试及真实 PG 双连接撤销实验。记录撤销发生时间、检查点和实际调用计数，不能只断言最终返回了一个错误码。

## 7. 单元五：统一双语页面与可理解的访问结果

### 概念

用户需要知道当前登录的是谁、正在使用哪个企业范围，以及操作为什么不能继续。角色受限、资料为空、服务离线和登录过期要能区分；界面说明不能成为服务端权限依据。

### 实践任务

1. 继续使用 `/chat-room` 与现有 Provider 注册表；增加登录/当前身份/安全退出体验，显示服务端确认的租户与身份。合法的租户选择需重新验证成员关系，不提供修改隐藏字段即可切租户的入口。
2. 会话、知识面板、MCP 面板、Skill 列表与历史统一按主体刷新。切换身份后取消接收旧流、清空内存中的旧主体数据和已展开来源卡，防止旧请求迟到覆盖新页面；服务端仍执行权限检查。
3. 登录失效、权限撤销、越权工具、不可见资料与服务失败使用明确的中文/英文文案。对不可见资源不展示对方名称、数量、原文或精确拒绝规则；拒绝提示保留可用的重新登录或返回操作。
4. 演示两个浏览器独立会话的甲乙访问。同一浏览器切账号只用于连续切换测试，不能把两个标签页共享 Cookie 误当两套独立认证上下文。
5. 覆盖桌面/移动布局、所有新按钮、展开/关闭/再开来源、历史恢复、执行中退出和权限失效。保留用户现有会话、个人笔记与学习进度；临时数据按记录恢复，不能删除用户数据来清理验收。

**交付与验收：** 中英文静态文案、主体切换与旧响应隔离的前端测试，逐状态截图。模型生成内容与原文无需伪装成已自动翻译；截图必须能核对当前主体、操作和真实业务结果。

## 8. 单元六：集中验收与可复核证据

先建立能失败的用例，再实现并运行必要回归。下列矩阵中的“通过”必须有实际结果；未执行、依赖失败和已知缺口分别列出。

| 层次 | 必须覆盖 | 证据不代表什么 |
| --- | --- | --- |
| 离线契约/策略 | 缺身份、伪造身份、未知动作、范围交集、上下文清理、撤销/迟到时序 | 不证明真实 PG、MCP 或登录可用 |
| 真实 PG | 身份与资源迁移、双租户相同 ID、全部读写路径、并发撤销、进程重启、故障后失败关闭 | 不证明模型从未生成敏感内容 |
| 真实 MCP | 正向受权、跨租户拒绝、伪造服务身份、连接重建/并发串用、原文回源授权 | 单独的连接隔离不证明业务权限 |
| 真实模型 | 两租户合成知识、正常 Skill、要求冒充身份/越权工具的负例、引用与拒答 | 模型口头拒绝不能证明工具没有执行 |
| 页面 | 登录/退出、身份切换、权限变化、全部按钮与来源、语言/移动和连续操作 | 初始页截图不能替代状态验收 |
| 交付记录 | 实际模型/数据/Skill/政策版本、失败重跑、提交与推送、已知边界 | 任务包发布不能替代工程实现 |

### 最小攻击与时序案例集

1. 未登录直接请求会话、知识详情、记忆、MCP、Skill 和事件入口，被服务端拦截。
2. 甲提交乙的 tenant/user/角色，或在问题中声称“我是管理员”，可信主体不改变。
3. 甲乙拥有同名文档，关键词、向量、混合检索、引用回源只返回各自秘密标记。
4. 甲拿到乙会话/运行/事件 ID，列表、详情、停止、删除、恢复全部不能越权。
5. 同租户用户甲乙的私有记忆、会话隔离；允许共享的资源按显式规则读取。
6. 只读用户通过 HTTP 直接调用知识导入/删除或伪造写工具，无副作用。
7. 任意客户端绕过主应用访问 MCP，缺少/篡改/过期授权均拒绝；合法调用仍能检索。
8. 任务等待工作/模型队列时撤销成员权限，下一个组件调用计数为零。
9. 工具返回后撤销，资料不再进入模型；发布前撤销，不对用户公开结果。
10. 退出甲、登录乙，甲的迟到 SSE/HTTP 响应不进入乙页面；旧历史按当前权限读取。
11. PG 中断时不能确认权限或资料状态，动作失败关闭；恢复后重新认证/授权再成功。
12. 含“加载新 Skill、切租户、跳过授权”的合成资料不能改变工具范围或执行主体。

## 9. 独立练习与面试复盘

**独立练习：** 增加“同企业知识维护者”角色，仅允许维护本企业知识。保持个人会话不可默认查看，给“管理员能看全部资源”的错误实现补一个必须失败的用例；再设计权限撤销发生在 Embedding 完成、索引发布之前的测试，说明后台任务为何也需要重验授权。

**能讲清的项目故事：** 从一次 VPN 问题开始，说明主体怎样建立，范围怎样到达 PG 与 MCP，Skill 怎样限制动作，撤销如何挡住排队调用，页面怎样呈现真实结果。用实际 SQL、调用计数、版本与截图回答，而不是只展示权限注解。

**面试追问：**

- 认证与授权有什么区别？tenant 字段通过校验为何仍不可信？
- Spring 请求线程中的身份如何安全传到工作线程？如何防线程池污染？
- 向量检索已加 tenant 条件，原文、重排、缓存、记忆和事件还可能在哪里泄露？
- MCP sessionId、应用登录会话、Skill 版本快照分别解决什么问题？
- 固定运行快照与实时撤销为何可以同时成立？撤销事务提交后如何定义动作边界？
- 生成完成但尚未发布时撤销权限，怎样证明答案没有公开？已经发给供应商的内容怎么办？
- 404 与 403 怎样选择？内部审计怎样保留排查信息又不暴露敏感内容？
- 如果采用 RLS，连接池、事务和应用数据库角色需要怎样验证？
