# 第十九课 · 统一对话页审批验收

Chrome 操作生产构建，使用独立浏览器上下文、合成 Skill 草稿和可控 HTTP 响应。截图中的账号、编号与回执为测试数据。两个身份的请求校验了 CSRF 头。审批和工单持久化另外使用正式控制器及真实 PostgreSQL 16.15 回归，模型生成与真实浏览器全链路仍待联调。

| 操作 | 预期 | 浏览器实际结果 |
| --- | --- | --- |
| 员工打开已完成会话并提交 | 显示待审批及可传递的编号 | [显示编号，员工没有审批入口](01-submitted.png) |
| 审批员展开面板并查看编号 | 显示原始标题、描述和可选决定 | [显示待审批草稿](02-inspected.png) |
| 点击批准 | 状态变为已批准，可单独执行 | [出现执行按钮，尚无回执](03-approved.png) |
| 点击创建工单 | 返回并显示工单回执 | [显示工单编号](04-executed.png) |
| 点击核对执行回执 | 同一请求返回原编号 | [编号不变，替身只计一次写入](09-replayed.png) |
| 查看第二份草稿并驳回 | 已驳回且无执行按钮 | [驳回状态](05-rejected.png) |
| 执行已过期且无回执的审批 | 显示过期错误，不显示成功 | [过期反馈](06-expired.png) |
| 切换英文 | 审批操作与状态切换语言 | [英文面板](07-english.png) |
| 审批会话被撤销后执行 | 恢复登录页，旧身份的内容消失 | [登录失效](08-revoked.png) |
