# 版本化业务 Skill

本包是项目自己的 Java 业务策略实现，不是通用 `SKILL.md` 执行标准。用户材料、模型文本和下载文件均不能注册策略、类名或工具。

## 职责

| 类型 | 职责 |
| --- | --- |
| `SkillDefinition` | 有界严格 JSON、固定执行类型、只读工具身份和 schema 摘要、不可变内容摘要 |
| `SkillCatalogue` | 仓库受审查的 IT 工单分析 v1/v2 定义 |
| `SkillRegistry` | 同版本冲突拒绝、默认指针、启用状态；选择时返回不可变定义 |
| `SkillExecutionPolicy` | 服务端、课堂身份、Agent 和 Skill 的工具交集；实时撤销 |
| `SkillRunner` | 澄清、查询、验证建议、未创建的工单草稿；共用截止、取消、两运行容量和审计事件 |

`SkillRunner` 包装并复用 `ResearchRunner`，不复制 MCP 协议、工具参数校验、模型排队、当前原文复核或引用编号检查。在给模型能力列表前检查策略和精确工具 schema，在真实 dispatch 前再次检查。最后发布草稿前仍检查取消、截止和实时授权。

首个策略的澄清采用确定性的课堂最小信息规则：已知 IT 产品/系统关键词与错误标识同时存在才进入查询。仅有任意数字不算 IT 问题。这个规则不是完整的语义工单分诊，仍可能需要人工补充影响范围、发生时间和环境；扩展该规则应发布新定义/执行器版本并补相应业务测试。

## 版本与事件

`SKILL_SELECTED` 保存完整定义、定义摘要、工具快照摘要、执行器版本、选择时策略版本和时间。`SKILL_STEP` 保存步骤状态与耗时；已有真实 `TOOL_*` 事件提供实际 callId、参数和工具结果。`SKILL_TERMINAL` 保存最终结果和当时快照。公开事件由已有会话层保存，历史无需拿当前默认定义重新解释。

默认 v1 可切换为 v2 后再回滚。已经开始的运行仍固定原定义；停用版本只拒绝新运行，在途运行继续，但实时权限撤销可以阻止下一次调用及草稿发布。v2 增加 `priority=NORMAL`，v1 的该字段为空，两者都明确 `created=false`、`requiresApproval=true`。这里只形成数据草稿，没有调用工单写接口、生成实际工单或执行审批。

## 边界

- 固定 `demo-learner` / `demo-enterprise` 是课堂服务端上下文，不是生产登录认证或多租户授权。
- 注册表、默认指针和实时撤权存在当前 JVM；重启从受审查仓库定义重建。这不是持久化发布平台，也不保证跨 JVM 发布一致性。
- 记录用于审计，不代表支持跨进程自动接续。旧运行的定义摘要不能替代恢复协议。
- 一次运行最多一次只读查询、两次模型调用，最长 30 秒；容量拒绝不排业务队列。模型排队、MCP 调用和来源复核继续使用剩余期限。
- 两个业务运行名额在本地运行返回时释放；忽略中断的远端模型工作可能仍占 `ResearchRunner` 的实际模型线程，后者继续受独立的两线程、八队列上限约束。不能把业务名额释放描述为所有后台资源已经退出。
- 取消是本地停止等待与阻止新调用；正在远端执行的只读操作不承诺立即停止，也不声称回滚。
- 引用编号与当前原文校验沿用第十五课。模型建议仍需分层模型验收；本包不新增独立语义判定器。
- 只允许固定知识工具。未来写操作还需要 operationId、参数指纹、审批主体/资源/版本绑定、批准后重验和未知结果查询，不能只扩大这个工具集合。

测试位置：`src/test/java/com/zxl/zxlaiagent/skills/`。离线测试不证明真实 MCP、PG、模型和页面已经验收；相应证据由本课集中验收记录分别提供。
